# 闸放错层：一道判据完全正确、却一次都没跑过的门

2026-08-23 · derivation 节点 · 由 benchmark 真跑暴露

## 一句话

`derivation_log` 的全部结构纪律挂在**冻结门**上，而冻结是模型自愿调用的动作 ——
一次真跑里模型从头到尾没调 `freeze_artifact`，于是那道判据一个字都没写错的门
**一次都没跑**，带着伪造验证章的产物照常交付，run 判 `completed`。

## 事故现场

benchmark 任务 `damped_resonance_width`，A1 臂（harness + v4-flash）：

| 观察 | 值 |
|---|---|
| `check_step` 调用次数 | 9（**模型真的逐步验过**） |
| step.verification 的形状 | 字符串 `"verified"` —— 工具返回的验证章被丢掉 |
| 模型自己发明的字段 | 用 `statement` 而非 `claim`、`tool` 平铺在 step 上、无 `justification` |
| `save_artifact` | 2 次，全部成功 |
| `freeze_artifact` | **0 次** |
| `main_result` | 缺失 |
| run 终态 | `completed` |

模型不是在偷懒 —— 它真的做了验证工作，只是**不知道验证章该长什么样**，
于是自己编了一个扁平结构。唯一写着 step 形状的地方是冻结门的**报错**，
而那道报错从没触发过。这是「契约必须送到调用方」的教科书形态。

## 三层同时失效

1. **引导说了，但引导不是机制**
   `harness.yaml` 第 207 行逐字写着"把返回的 verification **原样贴**进来……
   自己写的 `status: verified` 冻结门不认"。模型照样没做对。

2. **唯一的机制挂在自愿动作上**
   闸放哪层要按**对手是谁**推。对手是"不冻结就交付"，那闸就不能只长在冻结上。
   写入是必经的，冻结不是。

3. **完成面不查产物冻没冻**
   `unverified_artifacts` 是 provenance 审计，不是冻结状态；这个机制不存在。
   （没有为此改 executor —— 冻结是通用语义，动它会波及所有节点。
   改由收尾闸点名，先观察真跑效果。）

顺带一提，`harness.yaml` 里当时还有一句注释写着"冻结这件事由**写入面的冻结门**
接住（伪造验证章/未冻结产物写不进去）"—— **那句话描述的架构并不存在**，而且
自相矛盾（写入的那一刻产物本来就还没冻结）。最讽刺的是它紧接在
"留着比删掉更糟：它看起来是一道闸，实际一次都不会跑"后面。我诊断时正是被它
误导，以为写入面早有防线。

## 修法

判据**一个字都没重写** —— 两道门共用同一批函数（`_audit_steps` 等）：

| 门 | 什么时候跑 | 管什么 |
|---|---|---|
| 写入门（新） | **每次 `save_artifact`（必经）** | 这条链的**结构**成不成立 |
| 冻结门 | `freeze_artifact` 时 | 这份**承诺**兑现了没有 |
| 收尾闸 | 收工前一次（不硬拦） | 切题自查、还红着的式子、日志没冻结 |

框架侧补上了写入面的可注册门（`register_save_gate`），与 `register_freeze_gate`
完全对称：门跟类型走、契约随门一起渲染进 `save_artifact` 的说明。
此前写入面的三道闸全硬编码在 `builtin.py` 里，节点特有的类型契约无处安放，
只能挤到冻结门 —— **那正是这次事故的结构成因**。

## 顺带挖出的框架层 bug

`required_metadata` 只有"必须非空"一档，而冻结门早就有"必须在场、可以为空"
那档语义。于是 `assumptions: []` 被判成缺字段 ——
**一份假设为空的合法推导永远写不进去**（纯代数恒等式确实不需要额外假设），
模型只能编一条假设或者交不出产物。**闸反过来制造它要防的行为。**

修法：`artifact_policy` 新增 `present_but_may_be_empty` 类型级声明，
写入面分两档：查值 vs 查 key。
（`observation_log` 的 `findings` 疑似同病，但那是别人的节点，只提不动。）

## 真跑验证

判据在跑之前写下，逐条对：

| 判据 | 事故那次 | 修复后 |
|---|---|---|
| 写入门拦截 | —（门不存在） | **2 次**，模型被拒后去补验、再拒、再补验 |
| 形状异常验证章 | 14 条全是字符串 | **0** |
| 验证章可核验 | 0 | **13 条，账本反查 13/13** |
| `main_result` | 缺失 | 完整（source=`main_result`，不是从末步猜） |
| 产物冻结 | 从没调过 | **True** |
| 最终表达式 | `gamma`（功率曲线） | **`sqrt(3)*omega_0/Q`**（与 ground truth 一致） |

⚠️ **答案从错变对是单次运行，不足以归因到这批改动** —— 能确认的只有防线全部到位。
但值得记一笔：模型这次主动写明了"功率曲线(A²)的半高全宽为 gamma，相差因子 √3"，
正是上次栽进去的那个区分。

## 方法论：我差点报告一个假结论

上一轮我加的切题自查，"验证跑"读到的答案仍是 `gamma`，我已经准备写下
**"这道提示对模型无效"**，并据此考虑删掉它。

真相是：那次跑**根本没跑完**（driver 在解析产物时崩了），我读到的是**上一次**
留在同一个固定路径上的结果文件。救回来的不是测试（全绿），是一个不对劲的
时间戳 —— 结果文件比我改的代码还旧。

差一点造成的三重代价：报告假结论 → 删掉一道刚做对的防线 → 三个真缺陷继续潜伏。

而这次修复本身又栽了同一个病的第二层：切题自查改成"读不到就点名"之后，
真跑里它确实注入了，但注入的**永远**是"你没有 main_result"——
因为 `list_artifacts()` 的条目从不带 metadata，那段代码永远读到空。
单元测试没抓到，因为**测试替身自己实现了一个带 metadata 的 list_artifacts**。

三条判据，代价换来的：

- 写任何跳过分支时问一句：**跳过和通过，观测得出来区别吗**
- 验证自己的修复，先确认它**执行过**（找注入事件、找触发计数），再谈有没有效果；
  顺序反了，两种结论会被同一份现象支持
- **替身比真货宽容一分，就有一分的错漏测不出来** ——
  已补 `test_the_stub_matches_the_real_state_contract`，用真 State 钉住形状

## 遗留

- driver 的 `verification` 形状健壮化已修（字符串不再抛 AttributeError，
  形状异常单独计数）—— 测量工具不能因为被测对象形状异常而丢掉全部数据
- **未验证**：写入门对"不冻结就交付"仍然无能为力（它只保证产物形状合规）。
  这次模型冻结了，但那是收尾闸提示的结果，不是机制保证
- **下一步的候选**：让模型只点名"这一步对应哪次验证"（给 probe 或 lhs/rhs），
  由框架从账本补齐验证章 —— 与 `content_from_file` 同一个模式，
  **模型不搬运字节**。这次模型被拒两次后能自愈，所以它是优化不是必需；
  要不要做，看后续真跑里模型贴错的频率（先量再动）

## 后续（同日）：那个"框架层 bug"的修法本身也是补丁

上面写的修法是「`artifact_policy` 新增 `present_but_may_be_empty`，写入面分两档」。
**那是给一个不该存在的层加第二档。**

`required_metadata` 是**模式盲**的类型级近似，而 observation / derivation 的
metadata 契约本来就取决于 `metadata.mode`。近似必然对至少一种模式是错的 ——
`assumptions: []` 只是被撞见的第一例，同一行声明里还躺着两例：

| 字段 | 写入面（模式盲） | 节点自己的冻结门 | 后果 |
|---|---|---|---|
| `verdicts`（observation） | 全模式非空 | **不问** | exploratory 被硬禁勾账 → 天然无裁决可写 → 存不下来 |
| `credibility` / `verdicts` / `counterexample_search`（derivation） | 全模式非空 | confirmatory-only | 一趟合法 exploratory 推导存不下来 |

而 `credibility` / `verdicts` 这两个键**从一开始就翻译错了**：它们原本是两条
`artifact_content_regex`，查的是**正文**有没有 `## Credibility` 段、有没有裁决词。
搬到写入面时被写成了 metadata 键 —— 换了执法位置，也换了字段的落点，而
harness 的 `expected_outputs` 至今仍写着"正文含 `## Verdict` / `## Credibility`"。
于是模型每份记录写两遍，两遍必然各自演化；而 `metadata.verdicts` 全仓**没有
任何读者**（writing 的输入审计查 `closure_discharges` 或单数 `verdict`，
实测 5 份真跑无一写单数）。

**整层删掉**（`required_metadata` / `present_but_may_be_empty` / 访问器 /
`builtin.py` 里那段硬编码），契约的唯一声明权收回类型 owner 的契约模块，
由本文档上面刚建好的 `register_save_gate` 执行。这一层本来就是它要替代的东西 ——
本文档自己写着："此前写入面的三道闸全硬编码在 `builtin.py` 里，节点特有的类型
契约无处安放，只能挤到冻结门 —— 那正是这次事故的结构成因。"

### 顺带挖出的第三个洞：anti-HARKing 不冻结就绕过

`core.prereg_commitments._scan_result_metadata` 收兑现记录时**不看产物冻没冻**,
按类型（`carries_discharge_ledger`）扫全部产物的 metadata。而
"exploratory 不许勾账"这条**只长在冻结门上** —— 一份 exploratory 记录只要写了
`closure_discharges`、哪怕从不调 `freeze_artifact`，那些勾账照样进账本。

与本文档记的那次事故（9 次 check_step、2 次 save、**0 次 freeze**）是同一个形状：
**闸放哪层按对手是谁推，对手是"不冻结就交付"，闸就不能只长在冻结上。**
两个节点的这条规则都已搬到写入面。

### 判据重划

分界线不是"与模式有关无关"（原表述），而是**这一条判得动判不动**：

| | 写入门（每次 save，必经） | 冻结门（freeze 时，自愿） |
|---|---|---|
| 判据 | 只看这份 draft 自己就能判的 | 要**对照项目其他事实**才判得动的 |
| observation | mode / 取样纪律痕迹 / findings 结构 / 探索不许勾账 / 覆盖度算术 | 勾账键对不对得上冻结 prereg、confirmatory 的协议与分母 |
| derivation | mode / 链结构 / assumptions·findings 在场 / 探索不许勾账 | 闭合项对账、主结果验证水平、audit 裁决 |

判据函数仍然只有一份，冻结门跑的是写入门的**超集**。
