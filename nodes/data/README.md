按调用方明确范围，为下游 experiment/simulation 准备**直接可用**的前处理资产。

## 按需入口

调用方可以附带 `pre_registration` / `research_plan` / stage contract，也可以直接要求生成、
获取、检查或转换一个或多个明确资产。research plan 不是接单前提；直接请求只建立完成目标
所需的最小工作单元，不伪造 research stage。调用方已经确定科学范围，data 节点不选择、排序或延期假设。

入口统一规范化为版本化 `PreprocessingRequest`：research plan / preregistration 使用
`plan_bound`，用户或 experiment 的明确资产请求使用 `request_bound`。两者再编译为
`PreprocessingWorkOrder`；缓存、执行、审核和交付均绑定 `request_id + request_spec_hash`。

前处理生成入口先编译同一种工作订单：含糊文本和未提取的计划阶段按需调用 Requirement/Designer。
首次工单和定向修订统一通过本地 schema/safety、外部来源和 DAG 检查；不再让模型在
文件生成前预测质量或发布目录。已失败的旧工单不能复用批准，之后统一进入
Execute → Review → dataset。Review 由通用机械门禁和模型 authority review 组成；后者把产物
整体对照锁定的最初请求或 research plan，不得自行引入领域偏好或额外交付要求。

生产步骤拥有基础网格、显式几何变体和收敛网格，并将全部文件纳入执行检查点；
打包步骤只消费这些结果，缺少网格依赖时返回计划结构缺陷。相同 schema 连续失败
保留诊断，不另拼一个计划绕过失败。审核保留绑定实际文件哈希的小型原生测量，
大证据按需读取；成功状态不能覆盖质量门中实际失败的检查值。

## I/O 契约

| 方向 | artifact_type | 备注 |
|---|---|---|
| Input | preprocessing request | 明确资产请求；可选附带上游契约或本地路径 |
| Output | `dataset` | 仅完整实物交付，含 package、manifest、质量门和 lineage |
| Output | `preprocessing_document` | schema、获取计划或部分交付，不表示正式数据就绪 |
| Output | `preprocessing_blocked_report` | 缺参、外部阻塞或内部错误的证据 |

### 请求身份与交付状态

沿用 Framework 的 run/dispatch 身份、产物版本与来源，Data 绑定现有
`request_id + request_spec_hash`。结构化 `preprocessing_request` 保留为对象，
不将验收条件和派发说明混成几何描述。未接入调用方的 `data_request_envelope`
协议已移除；不再额外产生或强制要求 `data_delivery_receipt`。

任务结局写入 Framework 的 `node_task_outcome`，阻塞报告不是成功交付。
发布仍核对请求、审核回执、文件哈希和路径；只有完整实物保存为 dataset，
schema/获取计划/部分交付保存为 preprocessing_document。Data 不声明求解就绪。

模型传输失败在当前 Data 调用内退出；同步调用方结束本轮，恢复服务后才能继续。
已完成生产而审核失败时，保留检查点及累计审核成本，不能通过重新派发洗掉预算。
失败、暂停和取消均保留已下载输入，成功发布后才清理临时工作区。仅冻结已有交付时使用
`operation=freeze_artifact` 和唯一的 `artifact_id`；先核验审核回执及文件哈希，再调用既有冻结工具，
不进入生成流水线。修复目标必须是交付文件的实际写手或当前依赖链上的上游；退出生产路径的旧脚本
不能作为修复目标。非交付的同名编辑基线不能覆盖最终文件的资产身份。

## 验证边界

原生检查依赖见 `requirements.txt`。单部件平面 Abaqus 文件提供弹性/导热、网格、载荷及边界的
实测事实；无法解释的分析器几何提案不抹去其他测量。WRF 使用 f90nml 和版本化官方 Registry
检查字段分组、类型、维度时间和父子域接口，未声明版本时显式采用 4.6.1 参考定义；不声称运行了 WRF。
NetCDF 提供有限范围的真实读回与 CF 元数据检查，不把 bounds 缺少重复 units 判成缺陷。
规则经纬度网格的守恒审核使用独立球面重叠积分，报告缺测/覆盖排除范围；不以临时模型脚本的自检代替。
这些检查不声称覆盖全部求解器或全部 CF 规则，未覆盖的科学语义仍由需求审核负责。

缺参由需求分析结合原始文字与结构化契约判断，不另用字段缺失推断用户没有提供参数。
原子/粒子坐标必须经实际计算生成，通用打包器不代替结构生成；自编 Python 生产或审核脚本
均可修复，错误位置随诊断传回其写手。审核使用原始冻结快照，不把分析器提案提升为新要求。
Python 执行步骤允许声明它实际计算的结构/网格能力；结构恢复工具只用于已有结构来源。
外部来源尚未定位时保留必交付项，检索先补全位置和版本；同名但来源不同的文件不合并。
参考检索参数使用已注册工具的枚举，确定性生成的工单也必须经过同样的接口校验。
需求分析只提取当前调用的科学契约，不承担后续求解、产物生成或质量证明；运行环境目录
和调度器的扩展建议不能变成新的科学要求。提示词按职责集中描述契约，不累积重复的
执行策略；协议重试只纠正本次错误。规划日志的 `total_input_chars` 包括系统提示词，
不能只用 `payload_chars` 判断实际输入规模。推理 token 耗尽而正文为空不是网格缺陷，
也不能通过提高预算或跳过验收当作修复。响应速度、契约完整性和最终 E2E 分开验证。

文本产物的格式校验不将报告中的真实来源路径等同于运行占位符；脚本的运行接口和可移植性
仍单独校验，报告的测量真实性及交付路径仍由需求审核判断。无法应用的文本修订先在写手内部
用同一原文和原审核意见纠正协议；耗尽局部修复后带着原生诊断交给定向规划，不重复相同写法。
只有确实存在执行消费者的脚本才使用平台注入的输入/输出字典；独立复现脚本不假设该接口存在。

修改代码后的交付前检查以 `e2e_test_set.yaml` 为案例清单，按影响范围选择验证：确定不改变
科学流程的局部日志、交接字段或传输恢复改动做定向检查；较大重构或涉及共享需求、计划、
生成及审核判定逻辑的改动，回归所有已通过案例。新增案例加入清单并保留在后续回归范围内。
完整回归使用当前代码、隔离工作区和新产物，包含需求分析、生成、审核及必要的内部修复；
局部改动的定向检查可复核已有产物或验证受影响的协议，不必重新生成无关案例。
逐案报告运行结果和未验证阶段；离线协议检查、已有文件复核或直接 Data 流水线验证不能
冒充 Orchestrator E2E 通过。失败或外部受阻时不得宣称全部修复；临时测试代码验证后删除，
不另建或保留 test 目录。外发权限不足时先完成本地检查，并明确真实模型验证的缺口。
复测发现的框架缺陷须在同次修复中处理并再验证，不只记录失败；外部服务限制则保留真实
诊断和恢复位置，不放宽验收、不改换科学输入来伪装通过。

真实任务仍须以端到端日志和最终 artifact 为准，至少应看到：

- 每个调用方要求的生成 step 都有对应的 `artifact_id` 和落盘文件；
- 执行器返回成功状态，并记录文件路径、哈希和 provenance，最终 manifest/package 已发布；
- 没有 `blocked`/未解决的必需 gap，且下游要求的参数文件确实位于 package 内；
- 若脚本需要 `xarray` 等依赖，只记录为 `runtime_dependencies`；由 experiment 准备执行环境，
  data 不安装或运行环境管理命令。

执行缺库时，Data 返回 `externally_blocked` 报告；其 `resume_contract.handoff_request`
供调度器通过现有 `run_node` 调用 Experiment，在项目受管目录准备兼容依赖，不修改宿主 venv。
Python 依赖消费入口是 `node_inputs.runtime_environment_ref={artifact_id, sha256}`，并通过
`forward_artifact_ids` 显式转交对应操作产物；sha256 为 artifact 正文原样 UTF-8 字节的哈希。
操作产物 JSON 中的 `runtime_environment` 包含：`kind: python_packages`、绝对路径
`dependency_root`、`runtime`（implementation、python_version 为 major.minor、platform 为
sys.platform、machine）、`required_dependencies` 和非空模块名列表 `import_checks`。
Data 校验引用、兼容信息和目录既有可见权限，在本 run 的 `.harness/python-packages` 建立
引用，复用共享执行器的进程级 PYTHONPATH 加载，再实测导入及声明版本；不复制或安装依赖。
不根据“安装成功”的文字认定环境可用，不将路径声明作为扩权依据。引用不能在同一 attempt 内更换。
未提供环境引用的任务沿用原执行环境；显式声明的依赖在处理代码执行前检查，静态推断的可选
imports 不作为新增硬门禁。当前入口只加载 Python 包，原生 CLI/编译器仍沿用各自工具链适配器。
验证成功后，由调用方按 `resume_contract` 授权新 attempt 和新 child；不得复用旧 receipt。
若调用方尚无受控重试入口，应报告该限制，不得重复派发或绕过 managed dispatch。
失败退出仍清理私有下载；续跑按需重新获取，不清除脚本、诊断或已发布的用户产物。
下载正常连接保持单次 GET；断流后仅在服务器支持 Range、文件标识和字节范围一致时续传。
持续收到数据可继续续传，但受 `timeout_seconds` 总传输时限约束，连续两次无进展则停止。
耗尽传输恢复预算或服务端重试后仍失败时返回 `externally_blocked`，保留状态码、响应摘要和
字节进度，不重解释需求、不通过改写 URL 重试，也不将网络故障交接为缺库安装。
规划、审核、写手和参数修复允许客户端在原调用内恢复瞬态网络故障；整次响应时限包含
重试及退避，不另开一份时限。传输故障不交给模型重新规划，不重复已完成的生成步骤。
协议纠错及有进展的证据补读仍在原阶段继续；服务超时保留 checkpoint，不改写科学要求。
产物写入器只实现当前文件的职责，完整请求用于约束相关数值，不要求中间几何文件实现下游求解配置。
计划从结构化格式生成文件名时，`inp` 与 `.inp` 等写法使用相同扩展名；显式文件名及原生无扩展名文件保持原名。
下游组装缺少输入文件或所需格式时，诊断引用实际输入资产，由执行器修复其上游生产步骤并重建消费者。
材料和截面控制按分组值、扁平绑定值、执行参数依次读取；修复新增的受支持分组也必须生效。
区域条件的扁平键与分组键在现有绑定入口统一，几何生成和求解输入组装使用相同的区域定义。
Abaqus/CalculiX 组装在合并区域条件前对齐键的大小写，与其已有集合查找规则一致，避免旧值遮蔽修复值；其他格式保留各自命名规则。
相同牵引通过别名重复作用于同一组边时返回可修复诊断；空载荷条件可清除冗余别名，避免内部修复后叠加载荷。
写入器在落盘前拒绝精确回退到既有修复历史中的失败版本，并在当前响应纠错流程继续修正。
审核的软件上下文仅保留名称与版本；需求分析的识别依据、调度器建议不能借该字段新增交付要求。
配置的实际赋值段落与正文在同一次审核中核对，不另用模型盲猜字段归属作为强制规则；历史修复意见也须重新核实。
审核不维护应用字段白名单。证据不足时，在现有补读循环中提出 `verification_requests`：
用公共参考的定向摘录、本机已有定义或只读 Python 解析/测量核实具体条件。
复用共享工具的访问边界、风险确认及执行沙箱；不安装库，不启动完整求解，不修改待审资产。
执行检查仅开放选中的库存文件为只读输入和临时可写 scratch；参考内容属于数据，不是执行指令。
结果记录条件、验证范围、输入哈希、实际输出及来源，进入同一个有界审核证据窗口。
取回资料或退出码为零不等于产物通过；模型仍核对方法、目标版本和实际要求。
同一资产不重复执行相同检查，已有原生验证不重跑；缺工具与产物缺陷分开处理。
每次审核默认最多四个成功的外部/执行验证，总尝试数不超过该值的两倍，可用 `DATA_AUTHORITY_REVIEW_MAX_VERIFICATIONS` 调整；已取得证据的本地补读不占此预算。
公共资料保留完整只读副本，模型仅接收定向摘录；验证程序通过 `input_files` 的精确库存键读取实际路径。
取证与判定共用同一个审核循环，不增加配置专属前置阶段，也不靠模型自报的验证标记放行。
参考副本可在修复后按哈希复用，但旧产物的判定/检查结果不能沿用到变更后的文件。
定向读取的 `offset` 使用原文件行偏移，返回续读位置；库存键和已绑定的实际路径采用相同读法。
新增证据挤占阅读窗口时重新装箱，不把上下文预算变化误判为产物缺陷。已证明缺陷立即送修，不必补齐无关检查。
真实缺陷先修复实际生产者并重建依赖它的产物。局部实现无法修复时，保留原需求和有效产物，
只替换失败生产路径；允许一个旧步骤拆成多个新生产步骤，不能丢失必交付项。
审核传输恢复沿用项目配置的模型客户端重试策略，仍受单次审核总时限约束，不重生成资产。
生成与审核同时核对原生标量/数组的形状和索引含义，不把分析器的列表写法当成格式规范。
末端报告依赖实际资产生产步骤并读取其落盘文件，不按步骤名字排序抢先编造审核结论；有显式下游消费者的报告保留其原依赖角色。
写入器和生产器参数修复共用有界调用：首次保留低强度推理，最多使用 8192 token；截断时在同次调用内
用 `reasoning_effort=none` 和完整 32768 token 预算重新输出正文。首次小预算不是最终文件长度限制；
未得到完整有效响应时不落盘。规划和审核保持各自设置。
修复优先使用唯一锚点编辑；构造整体无效或锚点不足时，可携带原因返回完整替换正文。
两种方式不能混用；未变化或已拒绝的旧版本、真实占位内容及下游原生验证仍由原有检查拒绝。
修订已有产物时，当前 `operation_request` 参与请求身份和最终审核，不能被原始生成需求覆盖。
该字段必须显式提供；调度器的 `spec` 只是执行上下文，不能自动升级成用户新增要求。
输出契约的 `edit_source` 引用独立、不可替换的本地基线；`generation_recipe` 描述修改，
基线沿同一 DAG 传入文本写手或 Python 编辑器，并进入审核证据。缺失或含糊的基线不得用相似文件替代。
可见的历史交付只有在文件哈希吻合时才进入本地资产清单。Abaqus 的 `preserve_keywords` 声明
必须保持的数值块，由本地比较核验；基线丢失应修复输入绑定，不能反复修改输出或重新划分网格。
首次编辑可原样保留已经正确的文件，被审核拒绝的草稿仍必须产生有效修改。
用户明确给出的 Data 工作区前缀路径（如 `data/model.inp`）由发布器导出并核对哈希；
其他相对路径描述包内布局，不再让模型额外判断路径范围。角色名称不覆盖原生文件名，
目录资产逐文件保留结构及哈希。只复制已有产物允许零生成步骤；导出 I/O 失败保留暂存产物供续跑。
可用 `DATA_ARTIFACT_WRITER_REASONING_EFFORT` 覆盖，空字符串表示服务默认。服务明确拒绝该可选参数时，
在原调用内去掉该参数重试；格式检查、实际工具执行及科学审核仍须通过，不因写入速度提高而放行。
阶段阻塞报告从平台首轮输入收据提供可直接调用的 `resume_request`，无需重写原 spec；
需求一致性检查保持不变。调度器重派后成功不计作一次 Data 调用成功。
较大的 JSON 审核证据按原始子字段分窗读取，未读部分留在队列中，不把省略视为验证通过。

工单通过校验或 planning loop 完成本身不等于交付成功；缺少上述落盘和发布证据时，
应判定为“规划完成、交付未完成”，继续检查执行器状态，而不是重新搜索或重复制定计划。

SBML 交付必须通过 `libSBML` 原生解析与一致性检查，XML 能解析不代表 SBML 合法。Data Python
运行环境使用 `pip install -r nodes/data/requirements.txt` 安装此校验依赖；缺少时保留产物，返回环境
阻塞并从审核阶段恢复，不改写模型来掩盖缺库。原生错误交给文件生产者修复，警告不自动阻断交付。
审核响应若将输出预算全部耗在推理而无判定，沿用累计轮数和时间，在同一预算内切换为直接输出；
不增加轮数、不清空证据，也不把空响应当作通过。

执行、审核和规划统一返回七类 pipeline outcome：`completed`、`retry_step`、`revise_asset`、
`revise_plan`、`needs_input`、`externally_blocked`、`fatal`。审核失败只形成
`RevisionContract`；executor 优先修复产物及其负责步骤，并按 DAG 顺序重建受影响的下游，
保留无关成功步骤。生效参数和修复记录进入执行 checkpoint，后续修复不退回旧参数。
参数修复读取工具自身的 `content_contract`，可补齐原调用遗漏但工具支持的控制项；
不能只按原参数键集合限制修复。修复历史保留实际参数差量和文件哈希，不递归嵌套旧反馈。
标量控制不接收范围列表；Analyst 推测的范围不覆盖原生生产器默认值，调用方的冻结值
及向量/列表控制保持不变。无效控制的错误应列出具体字段，使内部修复能一次处理相关项。
实物片段只供审核和产物修复读取；规划恢复传递问题、负责步骤及修复摘要，不反复复制文件内容。
注册器的超长结果摘要仅用于模型上下文；executor 按受校验的本次运行文件指针恢复完整结果，
包括续跑 checkpoint。交付 manifest 不嵌套执行参数历史或重复的下一次调用载荷；
只有审核发布成功且取得 artifact ID 后，生成计划才能报告完成。
只有现有生成方法无法解决问题或 DAG 不完整时，才进入 Designer 调整局部路线，仍锁定原始需求。
一次修复无变化不直接判 fatal；重复无效修订由现有修订状态机停止。
修订计划未获批时，Data 在同一次调用内保留失败草稿、实物证据和原始审核意见继续修订。
局部修订持续无效时，复用 Requirement Analyst 重新核对内部需求解释；锁定的是调用方要求，
不是模型此前推断的文件名或生成方法。相同问题经局部修订及需求复核仍无进展才终止；
审核通信故障从成功步骤的 checkpoint 重试，不重生成已完成资产。
修复解决旧问题后暴露新问题也算进展，但文件变化不等于验收通过，交付仍必须重新审核。
建议文件名尚未匹配时，先由同一审核器根据真实内容完成资产绑定，不要求生产器重生成等价文件。
定向计划修订保留完整依赖接口；同一工具的局部修改合并参数，省略字段不删除已有输入引用或生效控制。
参数合并由 executor/planner 共用，不分别维护两套逻辑；更换工具时仍可重新设计局部路线。
OpenFOAM polyMesh 等多文件求解器网格默认附带 Tecplot 可视化导出；独立网格/输入文件
（如 `.inp`）不额外重复导出。调用方明确要求或关闭可视化时，保留 `write_tecplot` 选择。
可视化按实际单元维度导出：纯二维网格不强求体网格文件。OpenFOAM 的二维计算仍使用
单层体单元和 empty 端面；选择 OpenFOAM 转换时自动完成该存储转换，不改变物理维度。
生成或导出失败时保留 staged 文件和原始错误供修复，不把缺失质量数据解释成零单元或低质量。
审核数值约束时保留单位、参考系及“至少/至多/所有”的含义；实测值与约束的比较不成立时，
形成可修复的 RevisionContract，而不是用整体 pass 或原生工具检查通过掩盖不匹配。
模型审核用 `condition_checks` 将原始需求中的独立条件关联到可核查证据，不能只用少数参数证明整单通过。
模型提交条件、实际文件和简短观察，文件哈希由框架绑定；不再要求逐字摘录、引用索引或重复证明。
真实缺陷优先直接形成可执行修复意见；普通建议仅作 warnings。协议仅精简纠正一次，不重新生成资产。
证据概览与补读共享完整消息剩余预算，配置/原生报告优先；总输入默认上限为 64000 个编码字符，
包含提示词、工具 schema、需求和上下文，而不是另设一个固定的 10000 字符证据上限。
大型生产回执按带哈希的证据引用补读；JSON 数组和长字符串也可分页。未完成的相同请求续页，
被移出窗口的证据允许重读，不另设历史覆盖树和重复窗口否决逻辑。
概览和补读使用同一数值记录投影，小文件也不回灌整张数值表；短参数赋值、结构声明及原始行号保留。
机械统计由原生工具完成；必要实测缺失时返回具体修复意见，不让审核模型手算数据。
无裁决的输出耗尽进入同一次简短协议纠正，保留当前观察和文件；原样耗尽的请求不再重复续跑。
同文件多段/多 pointer 补读统一去重、分页；当前窗口和已完成观察进入现有执行检查点，
审核中断后接着复核，不从头补读。权威、上下文、文件哈希或配置变化后不恢复旧观察。
整份有效裁决只在权威、上下文、新增意见和所有文件字节完全未变时复用；变化后重新复核，发布哈希门禁不变。
普通请求只锁定调用方实际指定的文件名，Analyst 建议名称允许绑定到等价产物。
无进展判断复用稳定的问题身份和审核进展，不因模型改写意见、增加修复历史或更换计划 ID 而重置。
审核还可读取去重、限量的内部生成源文件片段；源文件不是额外交付要求。若缺陷源于上游，
用 `step_id`/`source_file` 指向能改变缺陷原因的生成步骤/源文件，而不是仅列来源。
审核同时看到步骤依赖和工具支持的修复控制项；executor 修复该源，再按 DAG 重建下游。
绑定中的参数名不代表每个工具都支持它；组装器不能靠修改网格参数修复上游网格。
Gmsh 质量统计提供各物理区域的实际坐标范围和线单元长度，不内置某种几何的合格阈值；
区域命名、范围和加密分布是否兑现请求仍由模型依据实物和配置联合判断。

## 关键工具

- `run_preprocessing_planning_loop` —— 从调用请求及可选上游契约推导前处理资产 DAG 并审批
- `execute_preprocessing_python` —— 计划授权后生成、检查或转换数据
- `prepare_scientific_mesh` —— 跨学科网格/粒子构型生成、已有 Gmsh 资产转换、缺参分流和质量审核的唯一入口
- `build_scientific_preprocessing_package` —— 只生成 staged 输入资产与发布候选元数据
- `execute_preprocessing_plan` —— 执行已批准 DAG，统一审核、修复、生成最终 manifest 并发布；不运行正式仿真
- `data_web_search` —— 在批准的发现目标内检索并检查公共线索，不直接把远程结果采纳为科学输入
- `data_web_download` —— 对选定 URL 执行安全下载、类型检查、SHA-256 和 lineage，生成可被后续步骤消费的本地资产

## 职责边界

- 从调用请求提取资产、必要参数、格式和验收要求；仅 plan_bound 提取既有阶段。
- 生成或转换请求要求的数据、几何/结构、网格和求解器输入文件。
- 对每项交付做机械审核，并由模型复核其是否兑现最初的 plan/request；不满足时只修复失败项。
- 缺少公开资产时定向检索；必须由用户确认的信息才进入 HITL。
- 最终保存可复现 `dataset` artifact。

## 不该做

- 自行提出研究课题、研究问题或科学假设
- 改写调用方给定的目标、阶段和科学判据
- 跑实验本身（experiment 节点的活）
- 解析实验/仿真结果或下科学结论
- 执行正式模型训练或长任务
