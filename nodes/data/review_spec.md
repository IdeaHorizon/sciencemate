# Data 节点内部交付审核规范（dataset）

Data 在发布前完成本地质量校验和模型需求审核，不依赖调度器重派或外部 reviewer 代为补救。
Gate Registry v3 只汇总需求兑现、质量证据和交付完整性；不按学科复制门禁。

## 节点内统一前处理审核

1. package reviewer 保留确定性的文件安全、存在/非空、格式及显式资产检查。
   拓扑、格式转换、原生工具检查等复用生产器已有验证结果，不再重复实现领域解析器。
2. authority reviewer 判断实际产物是否兑现原始请求/冻结计划，核对参数、单位、指定特征、
   空间分布和跨文件关系。原生检查通过只证明其检查范围，不能代替用户需求。
   目标存在不等于已被赋值或启用；局部加密看相邻区域尺寸差异，离散分布看权重与总量。
   等价表示不因语法不同而被否决，格式语义以已有原生证据/可靠参考为准。
3. executor 消费审核的 RevisionContract，沿实际生产者和 DAG 修复受影响资产及下游，
   然后复审；最终发布仍需三项 gate 通过。审核服务故障不是产物缺陷，不触发重新生成。

### 修复边界

资产或步骤的内容错误由 executor 在已批准 DAG 内修复，不因修复失败自动作废计划或转入
Designer。只有明确缺少生产者、依赖或阶段契约错误才授权结构修订。无法定位责任生产者
时保留该元数据缺口，不把猜测的修复步骤加入计划。未变化的独立资产不重建，受影响下游
必须重建后再审。递归修复与交付复审共用持久化执行预算，不能以变化的诊断或续跑清零。
重建消费者时新暴露的内容错误继续进入同一局部修复链，不直接退回规划。
调用修复工具前原子保存待修复诊断、编辑前指纹、已扣预算及下游失效状态，同时失效旧交付候选。
中断后先完成待修复步骤和依赖重建，再恢复审核；缺失的输出不抹除已修正参数，
部分写入不冒充完成，多个待修复生产者也不能被依赖重建覆盖而漏修。

原生检查只在对应操作被请求时生效，不适用项记为 `not_applicable`，不能伪造为通过或失败。
`derived_report_files` 标识工具计算的证据：若实物有效但报告生成逻辑错误，可用
`repair_kind=derived_report` 指出框架问题，不能通过调整科学参数或涂改证据迫使通过。
工具可通过 `report_rebuild` 声明可重建报告及 `reinvoke_preserving_dependencies` 策略。
只对声明的实际文件重放原生产者，保留原参数；调用前持久化依赖和无关交付文件的哈希，
重建后必须保持这些文件不变。未声明能力、无内容变化、修改受保护文件都不能算修复成功。
这条路径复用既有修复预算和断点，不是任意报告编辑器；生产者逻辑本身不支持的修复仍需代码修改。
参数依据区分 caller controls、executed controls 和未采纳的 planning proposals；规划建议保留
历史身份，不得作为实际执行参数或测量结果发布。旧 checkpoint 在报告重建时应用同一转换。
普通可编辑说明/统计报告仍走现有写入器；报告是明确修复对象时，其字节变化纳入进展判定。
服务/协议失败保持原产物和审核阶段；不支持的操作、无进展或预算耗尽保留原始具体诊断，
不升级成新的需求解释，也不能作为审核通过依据。

### 审核证据与判定

模型仅提交简短 condition_checks（条件、状态、实际文件、观察）和具体 issues（缺陷、
文件、修复建议，可选 step_id/source_file）。框架读取当前文件并绑定完整字节哈希，
模型不维护引用索引、不逐字抄写摘录、不提交重复数值比较/用途证明。
审核上下文分别保留当前交付文件的写入者与上游来源；转换后的文件不能仅因来源关联就归给
上游生产者。错误的文件引用与错误的条件状态分别诊断，目录引用会返回实际库存文件候选。
通过需覆盖全部明确需求及产物关键结构/设置的有效性；相关观察可合并记录，
不要求特定检查名称或再写一份同义结论。复用原生检查的已验证范围，不增加逐字段证明或额外执行。
同一产物字节的补读过程保留已解决观察，不按检查名称丢弃；产物变化后仍须重新审核。
发现真实阻断缺陷时立即返回修复建议，不必先完成全量通过清单。
可执行缺陷不因附带检查或资产绑定的格式错误而失效。
审核区分冻结要求、产物自身有效性和外部运行前提：未冻结不代表可省略必需内容。
非法字段/段位置、无效引用或使请求用途失效的实现选择属于产物缺陷，返回 issues 和
RevisionContract；不能因数值出现或缺陷已写入说明而放行。采用合法默认值或派生值修复，
不改变冻结条件，不要求额外仿真。配置类任务尚未提供的真实资源路径/源数据元信息、
合法默认值、可选字段和风格建议仍仅作 warnings，不能升级为额外强制条件。
配置合法性来自目标读取器或适用的官方资料，不另外用正则表达式建立配置字段索引。
读取配置时保留注释中的外部前提与误差说明；说明本身不是通过证据。
模型推测不是独立格式校验器；历史修改意见也须对照当前内容核实，不能将未经证实的段落猜测
变成强制规则，更不能据此来回搬移同一字段。真实错段仍沿现有生产者修复链处理。
不维护应用专属字段表。`needs_evidence` 可提出 `verification_requests`，声明条件、验证范围和
关联库存文件，按需取官方参考摘录、读已有本机定义或执行短小的原生解析/测量。
复用共享工具和执行边界，输入只读、scratch 可写、执行无网，不安装库或启动完整求解。
工具结果只作为证据，不直接变成通过/否决：资料取回成功不证明其适用，脚本 PASS 或退出码零
不证明科学正确；审核必须核对目标版本、实际方法和覆盖范围。缺工具不能冒充产物错误。
`measure_mesh_regions` 复用生产端的 Gmsh 读回和质量解析器，支持 MSH2/MSH4、ASCII/二进制，
返回拓扑、重复/孤立节点及四面体角点体积测量。可选 XYZ 包围盒按表面单元角点质心选择区域，
返回计数、面积及最长周边边长的下中位数。二维挤出网格须指定一个 Z 平面；空区域返回 null，
不能解释为零尺寸或通过。高阶曲边单元的角点测量不替代完整 Jacobian 检查。
分区范围由待验证条件确定，不内置翼型/圆柱接受阈值。JSON 读取错误返回当前节点的实际子路径，
分页窗口公开准确续读选择器；丢失原 JSON pointer/行号的字符偏移不得当成整文件偏移读取。
生产测量及完整原生检查通过同一证据库存传递，不在 executor 按字段长度丢弃，也不按前 N 项
静默截断。大回执只投影概览，原值按 JSON pointer/行段补读；概览省略不表示原证据不存在。
结果绑定实际输入哈希，进入原有分页窗口和 checkpoint；同一资产不重复运行相同请求。
局部修复后，仅当该回执的全部输入哈希未变时复用测量；输入改变时废弃旧观察，
由当前审核明确选择新的验证请求，不自动重放旧模型编写的 Python 检查。默认最多四项成功外部/执行验证，总尝试数最多八项。库存证据统一通过 requested_files 补读，read_file 只导入外部本机参考资料。
取证和判定共用现有循环，不另设配置专属阶段或以模型自报标记作为放行依据。
完整参考只读留存并可按库存键读取；验证方法和观察输出进入同一有界窗口，不把脚本输出当作原生权威。
参考副本按哈希复用，检查结果仍绑定当前产物字节；修复后不继承旧判定或未解决的叙述。
定向补读统一按源文件行偏移返回续读位置，库存键与绑定路径等价。
同一响应中的读取/验证请求均保留；新验证回执优先进入现有分页读取，不作为可被省略的概览，
也不先被旧补读的无进展判断拦截。验证方法与实际输出一起提供，不能把生成的检查脚本当作权威。
Python 检查在既有隔离临时目录保存完整有界 stdout/stderr，进入证据回执后清理临时文件，
不把共享工具的输出尾部冒充完整测量结果。小型当前配置在预算允许时保留，便于交叉比较。
同一审核上下文换窗时保留观察、取证目的和待读队列。上下文变化后不继承语义通过结论，
只复用输入哈希仍匹配的独立验证回执；同一权威和交付字节的累计成本不清零。
审核调用不携带整段历史对话，必须在现有 `condition_checks` 中记录部分事实及尚缺的比较项，
不能只写“还需检查”；最终裁决不继承旧的待核查占位项。取证目的不是已证明事实或新增条件。
同一条件补充或更换证据文件时更新原观察，不累计该条件的旧版本；当前响应明确返回的多文件观察仍保留。
当前窗口省略旧段落不等于从未取得，不能因此把整份产物审核从头开始。
窗口随新增证据重排，不因旧窗口超过新的剩余预算而终止。已证明的缺陷可以立即否决并送修，
不要求先完成其他条件的验证。真实缺陷继续送回原生产者，
重建受影响下游后复核；通信/证据协议故障不触发产物重生成。
字段形状及索引后的有效值也属于格式语义；不能把分析器推导的列表写法强加给原生标量。
配置概览保留合法注释中的默认依据、离散近似和运行前提；这些说明不代替实际赋值及原生测量。
产物有效性审核核对已写入字段的合法作用域和引用及参数值，不能以分组闭合或
说明文件的 PASS 代替语义审查。调度器结构化 `review_feedback` 作为非权威线索传入审核，不
回灌其扩写的整份 spec，避免建议值和附加输出再次污染原始需求；对照当前
实物核实；真实缺陷进入现有生产者修复链，合法默认值、未启用控制和运行前提不触发重生成。
缺字段先核对原生默认值及继承后的有效配置，不能以“未显式写出”推断无效；
未证实的格式规则只能列为不确定性提示，不能据此改写合法配置。
已授权且有效的默认值是已完成的实现选择，不再要求用户确认；运行前提的说明必须
明确不代表本次配置交付失败，不能以此触发整份重生成。
分析器的绑定映射不是完整目标格式规范；生成器核实字段所在段和实际生效关系，补齐
用途所需内容。定向修复沿现有生产者在当前文件上应用编辑，保留无关正确内容及成功依赖。
调用方未指定计数口径时，可保留已披露的有效原生约定；不能把另一种隐含口径
升级为强制条件。明确指定的单元数、格点类型、参考点或冻结数值仍严格核对。
这一规则不放宽物理量、几何距离或显式上下限。
只有完成需求确实需要调用方裁决时才 needs_input，不能反复索要已授权默认值的批准。
规划器的建议文件名、说明和 unresolved_facts 不能升级为额外验收条件；等价实物可绑定
至逻辑资产。显式文件名/位置约束及冻结参数仍必须满足。

概览及补读共用完整消息预算（含系统提示、工具协议、需求和证据），不另设固定证据上限。
配置/原生报告优先，大型数值表仅保留库存和概览；不据样本推断全体记录有效。
已由原生工具检查的解析、成员关系和连通性不逐页重做；必要检查确实缺失时反馈生产器补验。
暂存副本和源文件按字节去重；实际生产源文件不沿用规划摘要的四文件采样限制。
缺证据时只读取库存中的相关文件、JSON pointer 或一基行段，按完整行分页，
同文件可同时补读多段或多个 pointer，重叠部分去重，超出窗口的部分进入待读队列，
续页保留原始读取选择器；重复整文件请求从未读部分继续，按最新请求次序服务。
模型缩小或替换取证范围时取消过时的待读项，无新选择器时继续原队列。
不因文件名重复或正常分页消耗协议纠错次数。携带已完成观察而非累计全文；
最终裁决合并已完成的检查，不把上一窗口的“待核查”占位项变成额外验收条件。
窗口有余量时保留配置/原生报告概览，不能因补读数值表丢掉解释它所需的上下文。
概览只能使用补读之外的余量，不能因可选概览增多而丢弃刚选出的未发送证据；完整 JSON 已读块
不再附加同一内容的重复概览。长日志与同级字段共享分页，不让日志持续遮住相关的小型事实。
数值表概览中的 `L<行号>` 指向原始文件，避免模型猜测补读位置；前缀不属于文件内容。
预算内保留近期精确片段供跨段比较，已被窗口移出的片段可重新提供，不能只因历史上读过就拒绝。
仅在当前窗口去重，不维护另一套历史覆盖树或窗口进展判定；重复读取由累计会话预算约束。
审核窗口、待读队列和观察保存在现有执行检查点中，通信失败或取消后
续审仅在权威、上下文和实际文件哈希一致时恢复，不复用变更前的观察。
调整预算不清空证据或累计消耗；改变文件则使旧判定失效，但保留仍匹配输入哈希的独立测量。
二进制内容通过已有原生读取/测量证据审核，不能用文件哈希或头部替代内容验证。
完整原始需求不截断，缺陷和未读范围不伪装为通过。

协议问题仅允许一次精简纠正；通信重试由模型客户端负责，不在审核器再套一层。
同一审核会话默认最多 12 次模型交互、600 秒模型/取证活动时间，可通过
`DATA_AUTHORITY_REVIEW_MAX_CALLS` / `DATA_AUTHORITY_REVIEW_MAX_SECONDS` 调整。
取证、通信重试和超时均纳入已有 checkpoint 的累计成本；暂停等待下一次调用不计入活动时间。
续审不能重置预算。达到预算时保留产物、待补读范围、未解决观察及取证目的，返回审核阶段阻塞，
不改判为产物缺陷、不重新生成、更不能放行未核实的产物；显式增加预算后继续原会话。
输出耗尽且无裁决时保留暂存产物及阶段恢复契约，检查点记录实际请求指纹；
原样恢复不再次发送相同的耗尽请求。后端标记 length 但 JSON 完整有效时，可使用其裁决。
有效的整份裁决只在原始权威、上下文、新增意见及全部实物字节均未变时复用。
任意资产变化重新审核，不再拼接逐条件缓存/依赖闭包；历史通过不能跳过最终实物完整性门禁。
审核期间与审核后文件变化仍由发布哈希检查拒绝。

报告中的机械抄录一致性由装配步骤绑定的生产回执逐字段核对，包括实际单元数、执行控制和
原生检查结论；缺失生产测量不视为一致。该检查只证明报告未误抄，不能证明网格满足科学要求。
局部加密必须有加密区与参照区的实际单元尺度测量，不能用尺寸场设置或边界点间距代替。
模型只追查尚未解决的需求或具体矛盾，不新增“验证全部报告”的开放式任务；Python 取证应输出
计算结果及其范围，读报告字段使用现有补读接口。报告错误应重建报告并保留有效网格。

审核配置独立于规划/生成：
- DATA_AUTHORITY_REVIEW_MAX_INPUT_CHARS 默认 64000，包含实际序列化 payload、system 和工具 schema；
  这是字符上限，不是 token 上限。原始需求和元数据超限时明确报告，不静默截断。
- DATA_AUTHORITY_REVIEW_MAX_OUTPUT_TOKENS 默认 8192、最低 1024；后端需支持该预算，
  框架不静默下调用户设置。推理模型的预算通常包含思考和最终回答，提高预算不保证速度。
- DATA_AUTHORITY_REVIEW_REASONING_EFFORT 默认 low；空字符串沿用后端默认。
  这些设置不改变质量标准，不切换模型，也不影响其他阶段。
- DATA_AUTHORITY_REVIEW_REQUEST_TIMEOUT_S 默认 60 秒，限制一次传输的连接/读取等待，
  且不超过本次调用剩余期限的三分之一，为已有传输重试留出时间。整次调用仍受客户端
  timeout 和审核会话剩余预算共同限制；默认重试时间使用该调用期限，显式客户端重试预算
  和重试次数仍被保留。重试使用相同证据，不增加另一层重试循环、不重建网格。
  会话预算耗尽与模型调用超时分别报告，恢复时累计成本不归零。

终端只显示首次审核开始与最终结果，补读/纠错调用和耗时细节仅保留在 transcript。

通用数据转换的计划声明输入、方法、输出及验收条件，不在计划 JSON 中重复实现整段处理程序。
需要生成程序时，复用文本生成器产出内部脚本，由执行器通过 `script_asset`、`input_files` 和
`output_paths` 绑定并执行；脚本默认不作为用户交付物。执行或产物审核发现缺陷后，修复脚本的
原生成步骤并重建受影响下游，保留无关的成功下载。计划可执行不代表产物审核通过，最终仍按
实际输出复核原始需求；规划修订不得清空尚未解决的审核意见或重新解释已确认需求。

### Caller Stage Contract

调用请求及其可选上游契约是每个 stage 的参数和数据文件契约，而不是仅供说明的文本：

- 每个 `ready` 或 `candidate_generated` stage 必须写入 `parameter_contract.json`，逐项记录计划中
  显式参数、规范化后的有效参数、学科适配器实际读取的参数键、直接产物证据和传播/消费检查结果。
- 调用方明确写出的参数值高于分析模型补充值；模型只能补缺失参数，不能覆盖显式值。
  除已注册的规范化别名外，任何 `key=value` 参数都必须保留，使未预先适配的新学科也不会在规划阶段丢参。
- 参数存在于 `effective_parameters` 不代表已落实。`solver_input` stage 的每个显式参数必须被适配器实际
  读取，或能在用户提供的 JSON/YAML 等结构化输入中找到等值证据；否则 stage 必须隔离为不可交付，
  不能仅刷新契约后标记 `ready`。authority reviewer 必须复核实际产物是否兑现对应值。
- 调用方显式声明的 stage 必须全部进入工作流索引。分析模型可以补充语义，但不能
  静默删除 stage；当前缺少上游结果或适配器的 stage 应生成可恢复的 `input.pending.json`。
- stage 的目录和候选输入文件已生成，不代表其依赖已经满足。任何依赖前序求解、数据派生或实验
  结果的 stage，只有在对应结果 artifact 存在且通过最低可读性检查后才能标记 `ready`；否则必须
  保留已生成输入、标记 `deferred_dependency`，并在 `input.pending.json` 中写明准确依赖与恢复方式。
- 网格 stage 的单元数、域尺度、壁面/离散无量纲要求必须在生成前转成 mesher 控制，并以实际网格
  数量、域参数和已声明的预运行参考模型复核；通用质量下限通过不能替代计划要求通过。
- 求解器 stage 必须由对应学科适配器验证输入语法和可验证的数值控制，例如 CFD 的求解器、时间推进、
  CFL、黏度/雷诺数和边界速度，材料计算的 INCAR/KPOINTS/POSCAR/POTCAR 一致性。
- 审核失败优先修复负责该缺陷的生成步骤及其受影响下游，并保留无关成功步骤；仅当前方法无法
  修复或依赖图需要变更时，才进入定向规划及本地契约校验。科学验收始终针对实际文件，
  不用生成前的模型预判代替。几何、单位、边界语义或用户专有参数无法安全修复时，再请求必要输入。

### 通用交付目录约定

所有 data 前处理包按资产角色组织，不能以某个学科、求解器或网格格式命名公共目录：

- `stages/<stage>/`：阶段工作目录。`solver_input` stage 必须在本目录内保存
  可运行 case 及其运行时资产；`asset_generation` stage 只保存真实生成资产和质量记录，不能伪造
  求解器输入。网格只是 `runtime_assets.json` 中 `asset_role=mesh` 的一种资产；没有网格的研究任务
  不得生成空网格目录。
- 网格收敛 stage 必须使用 `mesh_convergence.json` 列出每个 level 的目标单元数、实际单元数、
  网格路径和独立质量复核结果。只有所有声明 level 都通过复核时，收敛研究根目录才可标记 `ready`；
  已通过的 level 可作为独立求解案例交付。不得用同一份网格复制到多个目录后声称完成收敛研究。
- 网格收敛只允许改变离散密度。几何来源、计算域、边界命名、近壁拓扑和显式第一层高度属于
  mesh-family 不变量，必须从基准网格继承并逐 level 比对。若研究计划声明壁面无量纲首层要求，
  仅有距离场局部尺寸而没有可报告第一层的网格不得标记为该要求已验证。
- 若 mesher 声明了表面/周向离散和边界层径向离散控制，审核必须分别检查它们随
  `coarse -> medium -> fine` 单调细化；只增加外部非结构区单元数而保持近壁周向节点和径向层数
  不变，不得作为合格的收敛网格族交付。
- 仅当调用请求明确声明 `mesh_convergence` stage 时，才启用三套网格流程；普通单网格任务不得
  自动创建 convergence level 或附加 `medium` 语义。三套网格收敛研究默认以 `medium` 为
  reference/downstream-default：先按正式仿真（包括 DNS）
  的计划约束生成并审核 `medium`，再从同一 mesh-family 派生更稀疏的 `coarse` 和更密的 `fine`。
  实际单元数必须随目标密度严格递增。公共可视化和后续正式求解 case 使用 `medium`，不能使用另行
  生成的公共网格替代。data 节点只交付可比较的输入；只有下游在相同物理与数值设置下比较
  `medium/fine` 的计划观测量并满足计划容差后，才能宣称网格收敛。
- 计划明确要求的收敛 stage 是当前前处理交付物，不是下游结果依赖。任一 level 生成或审核失败时，
  不得把该 stage 标成普通 `deferred_dependency` 后保存成功 dataset；应执行局部网格重试，仍失败则
  使 package review 失败，并把诊断集中到包级 `audit/mesh_convergence/`。
- `visualization/`：仅保存明确请求的可视化导出，例如 Tecplot、VTK 或预览图，不作为求解器
  运行输入。收敛网格使用 `visualization/mesh_convergence/<stage>/<level>/`，各 level 的 case
  目录不得重复保存这些文件。
- `audit/`：保存质量报告、审核结果、交付索引和自动迭代诊断，不作为运行输入。
  收敛网格的逐 level 记录使用 `audit/mesh_convergence/<stage>/<level>/`。
- `reproducibility/`：保存可复现所需的源几何、网格脚本、原始网格格式、转换参数及其哈希。
  收敛网格使用 `reproducibility/mesh_convergence/<stage>/<level>/`。
- 成功任务默认保存结构化验证结果；完整原始日志仅在调用契约明确要求或验证失败需诊断时保存。
  `.geo`、mesher journal、solver input 等原生工具输入已属于生成脚本/复现源，只有契约明确要求
  一键或可执行包装脚本时才额外生成 Shell/Python 脚本。
- `mesh_variants/<level>/` 只保留下游运行所需的输入、运行时网格、case marker 和参数契约。
  若求解器直接消费原生网格格式，该文件保留在 case 中并在 `reproducibility/` 保存副本；若已有
  独立运行时网格（例如 OpenFOAM `constant/polyMesh`），`.geo/.msh` 等只进入复现目录。
- 包根目录只保留跨 case 的 `manifest.json`、工作流索引和简短入口说明；不得同时放置公共运行
  网格、可视化副本、审核副本或临时说明文件。

`twoInternalFacesCells`、Finder `.DS_Store`、工具自动生成但未被下游契约引用的使用说明等
诊断/元数据文件不得作为最终交付物。系统可在生成期间使用它们，但打包完成前必须清理或转入
`audit/`。

## Gmsh 网格产物的节点内强制复核

当 data 节点通过 Gmsh 生成任何学科/算例网格时，data 节点必须在保存成功 dataset 前
自己完成机械复核与必要的自动迭代。该复核不等待 `_reviewer`，由网格工具直接执行并
落盘 `mesh_review.json`。标准参数化 CFD 算例可以通过 profile/role 叠加专项检查，
但所有后续新增 Gmsh 算例都必须继承通用 Gmsh 复核。

复核实现应分为两层：

- 机械质量层：所有 Gmsh 网格共用，包括文件存在性、OpenFOAM/Tecplot 导出、单元数量、
  非正面积、长宽比和拓扑完整性等确定性检查。二维域检查边界环、开口/非流形节点和连通
  区域；三维域检查边界壳闭合及非流形边。
- 语义意图层：先从用户需求、profile、生成结果中推断 `geometry_role`，再使用
  `nodes/data/review/mesh_reviewer.py` 中集中维护的 role 规则检查计算域、边界语义和
  加密区域是否符合物理意图。后续新增算例应优先映射到已有 role 或新增少量抽象 role，
  不要为每个 `mesh_type` 或每个公开几何在 `harness.yaml` 中增加专用分支。

`mesh_review.json` 必须记录 `mesh_intent`、`mesh_features` 和 `semantic_review`。
当语义规则发现网格域与用户任务不一致时，例如内部通道/周期流动被生成为外流远场域，
即使机械网格质量达标也必须判为 fail。

### 复核范围

- 通用文件完整性：`.msh`、`mesh_quality.json` 必须存在；如果生成器输出 `.geo`，
  `.geo` 也应列入 `written_files`；请求 OpenFOAM 时
  `constant/polyMesh/boundary` 必须存在；请求 Tecplot 时 `*_tecplot_surface.dat`
  必须存在。
- 通用网格质量：必须有有效单元；3D 挤出时必须有 3D 单元；不能有非正面积单元；
  `max_aspect_ratio < 500`。OpenFOAM 网格必须执行 `checkMesh -allTopology -allGeometry`；
  即使命令返回码为 0，只要输出包含 `Failed N mesh checks` 也必须判为失败。
- 通用导出一致性：`mesh_review.json` 必须记录 OpenFOAM/Tecplot 是否按请求成功导出，
  并记录失败原因。
- 几何形状：用户指定的几何必须来自显式参数、用户文件或可追溯公开来源；禁止回退成
  默认几何。外流绕流类任务必须保留物体孔洞/壁面和合理尾流域。CFD 导入 CAD 时必须先
  区分实体/轮廓与完整流体计算域；不得把物体表面直接挤出成流体网格，必须构造闭合计算域、
  从流体区域扣除实体并定义物理边界。
- 计算区域：外流、内流、周期通道、进口/出口通道等域类型必须与 `mesh_intent.geometry_role`
  和 `flow_topology` 一致；外流任务应保留足够远场和下游区域，内部/周期流动应保留入口、
  出口、周期或壁面边界。周期/弯折通道还必须检查参考边界形状、周期平移向量、实际节距与
  声明节距的一致性以及轴向域长度比例；只有矩形包围盒和 patch 名称不能证明计算域正确。
- 加密区域：近壁、尾流、边界层、局部曲率或用户指定区域的加密参数必须记录具体数值，
  并由 role-based review 检查是否满足质量门。
- 边界命名：OpenFOAM patch 名称应包含物理语义（如 `airfoil`/`cylinder`、`inlet`、
  `outlet`、`farfield`、`frontAndBack`）。

### 自动迭代要求

若复核失败，data 节点应自动调整网格参数并重试，默认最多 3 次。通用调整包括降低
特征网格尺寸、平滑增长率、修复导出流程；标准算例可叠加专项调整：

默认只保留最终可交付网格、`mesh_review.json` 和紧凑的审核结论；不得保留失败的 `.msh`、
`polyMesh`、Tecplot 文件或 `rejected_mesh/` 目录。需要逐轮复现实验时，才可显式设置
`retain_mesh_attempt_diagnostics=true`，并在 `audit/mesh_attempts/attempt_NN/diagnostics.json` 中记录
本轮 `.geo` 或生成脚本、质量报告、Gmsh/OpenFOAM 日志尾部、审核结果、结构化修复计划及其
SHA-256。对未被后续迭代覆盖的源文件可记录绝对/相对路径、大小和 SHA-256 引用，不重复复制同一份源文件；
最终可复现的 `.geo`、`.msh` 或生成脚本统一存放在 `reproducibility/mesh/`。
修复计划只能修改离散参数、网格算法配置、导出流程和可确定的 physical-group 映射，必须
声明 `geometry_or_boundary_intent_changed=false`；不得自动替换几何、计算域角色或用户边界
语义。OpenFOAM 转换后还必须记录显式期望 patch 与实际 patch 的差集。

对闭合轮廓或其他近壁边界，若边界层条带导致负体积、错误面朝向或不可接受的非正交，
允许在不改变近壁目标尺寸的前提下切换为距离场局部细化，并重新执行完整质量复核；
该回退必须记录在网格参数与 lineage 中，不能把未通过的条带网格作为最终交付。

- 远场/尾流过小：增大 `far_field`、`wake_length`。
- 表面/边界分辨率不足：增加边界离散点数或降低近壁/局部特征尺寸。
- 长宽比过大：适度增大第一层网格距离、降低边界层增长率、平滑近壁尺寸。
- OpenFOAM/Tecplot 文件缺失：重新导出或转换。

自动迭代中如果缺少新的几何/边界/质量门信息，必须先做信息分流：

- 可由本地 profile、KB、公开 benchmark 或论文检索解决的问题，应自动检索并记录
  `source_trace`，例如标准公开算例的常见域尺寸比例、边界条件描述、网格质量建议。
- 无法通过公开资料可靠确定的问题才进入 human-in-the-loop。私有/复杂几何文件、
  非 NACA 翼型坐标等几何本身通常需要用户提供；但如果用户已经提供几何文件、截面或坐标，
  只是缺少 CAD 单位/缩放、patch 物理语义、外围计算域、用户目标 y+、第一层网格距离或
  网格量上限等配套参数，必须先检索公开 benchmark、论文、
  算例说明或几何文件附带文档。检索失败、来源冲突或需要改变用户物理意图时，才 HITL。
- Re/Ma/入口速度/流体属性缺失时，节点应从任务描述或公开来源提取；仍缺失则采用可追溯
  预设并记录 assumption/source_trace。除非用户显式要求确认或工况参数相互冲突，不得仅因
  缺少流动工况启动 human-in-the-loop。
- human-in-the-loop 提示必须明确说明需要用户提供或确认的字段、不能自动猜测的原因、
  以及用户回复后节点将如何继续网格生成和复核。
- 非翼型任务不得复用 NACA/非 NACA 翼型缺参提示；新增或未知任务必须使用对应抽象
  profile、通用几何提示或公开检索提示。用户明确要求从网络/公开资料寻找
  几何参数时，应先走公开参考检索并记录来源，不能重复询问同一个本地几何文件。
- 内部通道、周期通道或级联流动不得默认套用孤立外流远场域。对应 role 应检查其必要的
  几何尺度、入口/出口范围、周期边界配对、壁面和通道区域。若使用物理上不匹配的近似域，
  除非 manifest 明确标记为已确认的非物理近似可视化，否则 reviewer 应判为不合格。
- 运行时不得维护特定学科的 case/profile 注册目录。请求或规划模型应选择已注册的通用
  生成能力，并把具体几何、参数和公开来源写入本次 `source_trace`。
- 几何来源优先级必须可审计：用户提供几何文件时必须优先使用该文件生成网格；未提供时先
  判断是否属于节点内已有参数化生成器的简单标准流动；这些任务应先本地生成。
  其他任务再检索公开几何；公开检索失败后才
  human-in-the-loop 询问用户是否能提供几何文件或确认候选来源。违反该顺序应视为流程问题。
- 该检索优先规则适用于所有网格类型。任何几何文件/截面/坐标已收到但
  外围计算域、边界语义、单位/尺度或网格目标不全的任务，都应先返回 `needs_reference_search`
  并记录检索查询；直接反复要求用户补同一类参数应视为流程问题。

只有 `mesh_review.status == "pass"` 时，网格工具才能返回成功并允许保存 dataset。
多次迭代后仍失败时，必须返回 error/needs_review，并在结果中包含
`review_iterations` 和最后一次 `mesh_review`，设置 `deliverable_valid=false`，并把失败资产
移入诊断/拒绝区。不得复制、打包或把失败网格总结为成功。
