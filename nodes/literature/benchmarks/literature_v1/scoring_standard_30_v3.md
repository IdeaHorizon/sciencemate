# LiteratureBench 30 题：学术检索多维评分标准（v0.3 草案）

适用任务：`tasks/balanced_natural_language_30_v3.yaml`。**比较对象是 ScienceMate 与其他 AI 平台面向用户的学术文献检索结果**；ScienceMate 对应前端学术检索页及后端 `/api/v1/literature/search`、`/api/v1/literature/search/stream`，不是 literature E2E 节点。每个平台每题固定保存最多 100 篇有序结果；前 20 条逐篇深评，前 10 条专门评价排序。候选池合并所有参评平台结果和独立检索种子，按 DOI 优先去重后统一盲评。不评回答文风、综述写作、全文获取、图片和平台私有研究产物。本 v3 由 v2 试测后明确范围，必须在正式评分前冻结题目、运行条件、候选池、标注手册与评分代码。

## 1. 与平台线上排序分的关系

平台 `nodes/literature/tools/filter.py` 的 `quality_score_breakdown` 将查询相关性、期刊分区、引用量和时效性拆开记录；期刊论文当前权重分别为 70%/10%/10%/10%，非期刊为 70%/15%/15%。这是**被测系统自身的排序策略**，不能直接作为 benchmark 的标准答案，否则会奖励与平台相同的算法。benchmark 保留“相关、学术价值、时间、可核验”等维度，但用独立证据和盲评判定。

期刊分区、影响因子、被引数、作者声望仅作为解释排序的诊断字段，不参与主分：学科之间不可直接比较，新论文有引用时间劣势，高影响力期刊也不能替代对具体论文方法的判断。记录这些字段时必须注明来源和查询日期，缺失不得臆造为 0。

## 2. 运行与标注单位

1. 六个大领域共 30 题，题干原样提交到学术检索模块；每题独立请求、一次检索、300 秒上限；技术失败最多原样重试一次，保存全部尝试、耗时及原始排序。主测试按用户界面的默认 `remote_refresh=false` 运行，另行记录 `search_mode`、来源、缓存与学校馆藏配置。若测试强制远端刷新，作为单独实验，不与默认模式混算。
2. 各平台使用同一题干、检索日期、数量上限和可比的时间预算；不为某个平台单独补关键词或追问。每个平台前 20 条全部进入候选池，第 21–100 条按相同固定规则抽样；独立检索者另补关键种子论文。合并去重后由两位评审统一标注，仲裁完成才冻结 qrels。相关度≥2的条目构成 Gold Set 正例，相关度0–1的条目是已判断负例；二者都保留在 qrels 中。
3. 两位领域评审者独立、盲于系统名称和名次标注。每个判断保存证据链接和一句理由；有分歧时由第三人仲裁。书目核验与学术判断分别记录，不能用机器生成的相关理由代替原始摘要。参评平台结果未全部进入候选池、存在未判断的前20条或仲裁未完成时，不得发布平台排名。
4. 优先检查摘要、出版方/机构页面与可用的研究方法信息；若这些材料不足以判断研究设计，记 `unknown`。必要时可核对正文，但被测系统**无须**提供全文。缺摘要、无 DOI 不自动判为低质量或虚构。

接口批量留证可使用现有 runner（其默认仍是旧 ESI 任务，必须显式指定本题集和 benchmark 采用的 100 条上限）：

```bash
export BENCHMARK_API_BASE=http://127.0.0.1:28081/api/v1
export BENCHMARK_ACCESS_TOKEN='从测试账户取得的 token'
python nodes/literature/benchmarks/literature_v1/run_harness_search.py \
  --taskset nodes/literature/benchmarks/literature_v1/tasks/balanced_natural_language_30_v3.yaml \
  --limit 100 --system-name 'ScienceMate 学术检索模块' \
  --out nodes/literature/benchmarks/literature_v1/results/sciencemate_nl30_run1.json
```

此 runner 调用 `/literature/search` 保存结构化响应；用户界面使用 `/literature/search/stream`，目前页面默认请求 200 条。本 benchmark 固定请求 100 条，评测结论须注明这一参数，不能声称复现了页面默认 200 条的完整体验。两种接口调用同一个 `literature_search` 业务操作；用户体验复核还需检查流式接口的 `done/error` 事件及最终页面展示顺序。学校馆藏是否启用、账户、索引快照和缓存状态要随每次运行存档。

**深层页面检查**：第 21–100 条保留全部顺序和字段，逐条程序化检查 DOI/URL 格式、书目字段缺失、类型异常、跨页重复和与已标注关键论文的命中。DOI/URL 可达性与题名对应关系需要逐条自动核验或人工复核，不能仅凭字段非空算真实。按实际页码在第 2–5 页各按预先固定的随机种子抽取 2 条（每题最多 8 条）做同一套人工相关性/证据标注，并报告每页样本数及不确定性。这是深层质量抽检，不能把样本均值冒充全部 100 篇的准确率。若要宣称整个结果集的相关率，必须把全部返回论文标注完。

## 3. 单篇标注表

| 字段 | 判定规则 |
| --- | --- |
| `relevance` 0–3 | **3** 直接回答题干主要问题；**2** 直接覆盖至少一个问题要点；**1** 仅背景或共享关键词；**0** 与问题无关。按内容判，不按期刊名或引用数判。 |
| `evidence_quality` 0–3 / `unknown` | 对**该题所需证据**的可信程度：**3** 设计适合问题，有充分对照/验证或扎实的一手材料，关键限制可识别；**2** 方法和结果可核查，但验证范围或限制较大；**1** 初步、间接或仅观点性证据；**0** 有可确认的严重方法缺陷，不能支持所问结论。资料不足记 `unknown`，不得猜测。 |
| `reference_status` | `verified`：DOI 对应题名，或稳定出版方/机构原文链接对应题名；`invalid`：标识符指向别的作品、明显虚构或无法成立；`unresolved`：暂时无法核验。无 DOI 但有可核验原文可为 `verified`。 |
| `facet_ids` | 该论文**直接支持**的预先固定问题要点；仅关键词重合不能覆盖要点。 |
| `year_fit` | `fits`、`out_of_scope` 或 `unknown`，只依题干及预设时间规则判断。不要求新论文一律优于经典文献。 |
| `bibliography` | 标题、作者、年份、出处、DOI/稳定原文链接分别记录是否准确、缺失或冲突；链接存在不等于内容正确。 |
| `item_type` | 原始研究、综述、会议论文、书/章节等；题目排除的新闻、书评、编辑告示、更正/撤稿通知等不能充当有效研究。 |

证据质量的题目锚点必须在正式运行前写明：临床题看研究设计、真实患者与外部验证；工程题看实验/现场验证及对照；社会科学题看识别策略、数据与外部效度；人文题看一手材料、文本处理和论证。综述看检索与纳入方法、证据归纳和局限；预印本可以入选，但审稿状态单列，不自动判低分。`reference_status=invalid` 的条目保留原始相关性标注供审计，但在系统得分中不计相关、证据或覆盖分，同时单列“虚构/错引”率；`unresolved` 暂缓正式计分，不能直接算虚构。

## 4. 每题分数：各维度独立按 100 分报告

**不计算加权总分、不做跨维度平均、不据此发布综合名次。**每项独立展示 0–100 分及原始分子、分母。先对同一文献的重复出现只保留首次的得分，后续位置计 0；少于 20 条的空位计 0。若问题点、核验或证据标注尚未齐全，该题相应维度显示 `未评分`，不得把缺失偷偷当 0 或只在已标注结果上报高分。

| 维度 | 独立百分制计算口径 |
| --- | --- |
| **前排相关与排序** | `100 × nDCG@10(relevance)`；3/2/1/0 为分级相关性，理想排序来自同题已标注候选池。另报 `P@10` 的百分比。 |
| **论文证据质量** | `100 × EQ-nDCG@10`。仅对前 10 个位置，合规且相关性≥2 的单篇增益为 `evidence_quality/3`；其余、无效引用及重复项的增益为 0。以同题候选池的理想排序归一化；`unknown` 未仲裁前暂停该维评分。相关性只作为入选门槛，不与证据质量相乘或合成。 |
| **问题要点覆盖** | `100 × 已被至少一篇前20条、相关性≥2且可核验文献直接支持的要点数 / 预定要点总数`。只计不同要点，不因同一要点堆论文加分。 |
| **引文真实性** | `100 × 前20条可核验且书目身份一致的条数 / min(20,实际返回条数)`；空结果为 0。另报 `invalid`、`unresolved` 的条数与比例。`unresolved` 项须核完或注明无法完成，该维正式评分暂缓。 |
| **有效研究数量** | `100 × 前20条去重后、相关性≥2且类型合规的篇数 / 20`。固定 20 为分母，避免只返回一篇高相关文献就拿满分；另外报告原始返回数和重复率。 |
| **书目准确与完整** | `100 × 准确且完整的标题、作者、年份、出处四字段数 / (4×实际返回条数)`；空结果为 0。字段错误不能按“已填写”得分。另报缺摘要率和类型错误数。 |
| **时间适切性** | `100 × 前20条相关性≥2且满足题目预设时间要求的篇数 / 前20条相关性≥2的篇数`；无有效文献为 0。若题目没有时间条件，预先标为 `N/A`，不凭“越新越好”打分。 |

两个 nDCG 均按 `DCG@10 = Σ(gain_i / log2(i+1))` 计算，`i` 从 1 开始，除以同题候选池按相同增益排序的理想 DCG；相关维度取 `gain_i = 2^relevance_i - 1`，证据维度取表中给出的连续增益。`EQ-nDCG` 的理想分母只使用候选池中已经完成双标和仲裁的合规文献；若没有正增益，证据质量维度记 0 并说明候选池状态。`nDCG@10` 的未标注文献不能默认相关性 0。`P@10` 固定除以 10，相关性≥2 才算命中。前 20 条的真实性和元数据在数量上按实际返回条目计算，避免“只返回一篇且真实”被误解为检索全面；有效研究数量维度保留固定 20 的分母。

**运行指标单列**：首轮成功率、最终成功率、超时/限流/错误数、端到端耗时中位数及 P90、重试累计耗时、成本（若可核实）。成功率以百分比展示，耗时和成本保留物理单位，不强行转换成质量分。另报完整返回集（最多 100 条）的总篇数、跨页重复率、书目字段完整率、类型异常率、可核验链接率及深层抽检结果，并与第一页指标分开呈现。失败或空结果的题在可计算维度中计 0，不能从均值中删掉；`not_offered` 单列，不把平台没有的私有功能当检索失败。报告分数的同时报告每维有效题数和未评分原因。

## 5. 汇总与发布门槛

- 展示逐题**七项独立百分制分数**、每领域每项均值和失败记录。对每一项，先在各领域内平均，再对六领域等权平均；同时给出该项的 30 题直接平均作为敏感性结果及不确定区间。`N/A` 题不参与该维均值，并逐领域报告有效题数。不得把七项相加或平均成一个总分。
- 测试本平台模块时，保存后端原始响应、前端最终显示顺序和模式参数；若二者不同，以用户实际看到的顺序为主，差异另报。流式接口以 `done` 事件作为完成，流内 `error` 也计失败。若将来与其他产品同题对比，须统一题干、输出上限、时间预算和运行条件；新增文献补入候选池完成双标，不能拿旧 gold 将新结果一律判 0。人工判断盲于来源，保存仲裁记录；对 `unknown` 和 `unresolved` 报覆盖率。
- 正式报告须完成全部 30 题各系统原始结果留存、候选池补全、双人标注及仲裁、DOI/URL 抽核、指标实现和复算。未满足时仅发布试点数字，不给正式逐维排名。
- 现有 `score.py` 只实现旧 ESI 任务的部分指标，**尚未实现本文件的独立百分制**。本标准是待冻结的评分草案，不是已取得的 benchmark 成绩。

## v3 范围说明

- NL10：允许包含小麦与小黑麦的比较，但论文须单独报告小麦结果。
- NL17：补充两部文学作品的英文原名，消除专名翻译失败造成的检索词波动；研究问题与判定对象不变。
- NL18：有学术论证的专著章节属于合规研究；新闻、书评、会议记录与仅转载的决议原文不属于合规研究。
- NL20：主任务只测重排序对回答质量的直接影响；错误引文单列为 `tasks/supplemental_citation_validity_v1.yaml` 的 NL20C，不并入 30 题均值。
- 题目修改及额外探针均属新版本，严禁将 v2 与 v3 的成绩当作同题直接比较。
