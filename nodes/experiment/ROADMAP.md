## 2. 顶层目标、设计和松紧边界

目标是专业的实验执行者，而不是流程审批器：用户目标/输入/授权 → 父节点准确派发 →
Experiment 探测与可调整计划 → Core 权限和生命周期内实际执行 → 专业检查、诊断与纠正 →
结果、证据和可恢复状态交付。完整链条用于选方向；每次交付一个高收益、直接可用的改进，
不要求每项小改动先补齐全链，不由零散 bug 决定路线。

正式目标、授权、物理事实、证据真实性和作业责任必须可靠；步骤、核验方法、报告组织允许
纠正。检查须执行并报告适用性，不等于科研结果必须好。不能把无关失败变成全局成功门，
也不能把已观察到的交付矛盾忽略掉。不增加模型登记手续或软件/LLM 专属分支。

| 事实与 owner | 必须可靠 | 允许调整 |
|---|---|---|
| A：用户、父节点、正式契约 | 原目标、正式输入、版本和授权不被暗改 | 合法来源纠正任务并保留版本；模型解释不能冒充用户原文 |
| B：平台/执行器/调度器物理事实，节点维护 provenance | 准入、资源、提交幂等、真实动作、输出身份、终态和作业责任 | 合法诊断、重试与方法调整；不覆盖旧尝试或伪造副作用 |
| C：Experiment 交付与证据 | 成功绑定当前 A 和相关 B，不能成功也诚实交付 | 核验方法、报告组织、错误解释可纠正；科学意义交下游 |

不新增第四套 authority。大型任务仍需简洁可调整的工作计划，但计划不掌管权限、
物理状态或收尾；不恢复 declared_route 手续，不要求模型管理内部 ID。
scope 是描述不是交付门；无 prereg 不等于 operation，真实 prereg 约束按适用动作生效。
三件套是证据接口，不为凑齐材料伪造结果。不可逆风险事前限制，生命周期不变量自动执行，
结果按适用检查核验。专业能力进入方法、skill、检查器和 adapter，不按软件或 LLM 品牌加内核特例。
