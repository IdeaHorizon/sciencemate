# checkpoint 续训恢复核验

用于诊断、迁移或证明训练 checkpoint 的恢复能力。它是按任务选用的方法，不是每个 AI 任务的
全局门禁；纯推理和用户明确允许的 weights-only warm start 不要求证明训练轨迹连续。

## 先声明恢复等级

- **纯推理**：只核对推理所需的权重、缓冲区、配置与预处理兼容性。
- **warm start**：明确允许只复用全部或部分权重；新的 optimizer、计数器或数据顺序是新训练，
  不称作从原训练继续。
- **继续训练**：恢复任务所需状态，并从正确的下一批数据和下一次更新继续。
- **同轨迹恢复**：除继续训练外，还要在任务允许的确定性范围内与不中断分支保持短轨迹一致。

只检查所声明等级和实际算法适用的状态；未使用 optimizer、scheduler、scaler、随机过程或
可恢复数据游标时，不为凑清单制造它们。

## 定义 checkpoint 契约

在需要继续训练或同轨迹恢复时，先记录或建立：

- 确切持久化文件（或框架定义的一组文件）的路径、大小/摘要与保存点；不要只依赖文件名中的
  epoch，也不要把内存字典当成持久 checkpoint。
- checkpoint 的 format/schema 版本，以及会改变恢复语义的配置身份：模型结构、数据与预处理、
  optimizer/scheduler/精度策略等相关配置和代码、框架版本。可写入 checkpoint，也可绑定到不可变
  companion manifest；不要求保存与恢复无关的全部配置。
- 该等级适用的可变状态：模型参数和缓冲区、optimizer 状态、已使用的 scheduler/scaler、
  已完成的 update/micro-step，以及确需连续性的 RNG、sampler/数据游标。优先在完整更新边界保存；
  若必须在累积中间恢复，还需覆盖未完成更新的真实状态。

## 从持久化文件实际恢复

任务要求证明“重启后可续训”时再做本节有界执行；只读诊断先核对已有文件、代码与日志，
不为分析而追加训练。实际迁移 checkpoint 时也按迁移目标选择适用检查。

1. 保留原文件，确认来源与读取边界；不要先用同进程对象“修好”待测 checkpoint。
2. 启动独立的 **fresh process**，只从记录的持久化文件或文件组读取。构造与配置身份兼容的对象，
   按所用框架和版本规定的顺序恢复；加载调用成功本身不证明状态匹配完整。
3. 在选择/读取下一批数据或执行下一次更新前，恢复该等级全部适用状态。若对象构造会消耗 RNG，
   应隔离该副作用或在构造后恢复 RNG；不得让验证代码先推进数据游标。
4. 检查缺键、多余键、shape/dtype、设备映射与恢复状态。TensorFlow 等框架可能延迟创建变量或
   延迟恢复，应在首次使用/更新前完成匹配，并使用与声明等级相符的 status assertion。

## legacy、部分状态与降级

legacy checkpoint 缺少当前等级必需字段时，不要静默用默认值补齐后仍声称 faithful resume：

- 若使用部分权重加载或 `strict=False`，检查实际 missing/unexpected keys；若跳过该恢复等级
  必需的参数或缓冲区，不能只据“加载成功”宣称完整恢复，应按任务显式降级为 warm start 或拒绝。
- 若任务要求继续训练或同轨迹恢复，则拒绝该声明或交付 partial/blocker，精确列出缺失字段、
  可迁移范围和下一步。只有语义有依据且结果可验证时才迁移，并保留原 checkpoint。
- 纯推理不要求训练状态；optimizer、RNG 或数据游标缺失不能单独否决合格的推理产物。

## 有界短轨迹验证

需要证明普通续训时，恢复分支在首次更新前先核对已完成更新数、学习率、下一批/样本身份
及适用状态，再运行少量预先限定的更新。只有要求同轨迹恢复时，才从同一保存点建立可比的
不中断参考分支，与从持久化文件启动的 fresh-process 分支比较等价更新。

- 按任务选择 loss、模型输出或权重/状态增量等可比观测，不用“脚本跑完”代替轨迹证据。
- 对浮点量预先说明绝对与相对容差及依据；比较数值本身或结构化状态，不比较格式化日志字符串。
- 跨设备/版本或非确定性算子可能无法逐位一致；此时核对必须保持的不变量与有意义的误差范围，
  披露剩余差异，不能事后放宽容差来制造通过。
- 若兼容行为属于任务范围，可加入 legacy/weights-only 负例，确认它被明确降级或拒绝，而不会
  冒充完整恢复。

交付记录 checkpoint 与配置身份、fresh-process 命令/进程边界、框架版本、比较观测、容差、
实际结果和限制。对不可信来源不执行不受限反序列化；安全加载模式失败时不要自动放宽。
