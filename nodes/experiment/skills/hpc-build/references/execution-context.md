# 执行目标与工具链一致性

用于环境选择、工具链复用或路径含义存在疑点时。已有同目标、同版本的可靠记录直接复用；
不要求每条命令重新探测，也不新增环境登记表、授权缓存或路径转换规则。

## 先辨明证据属于哪里

区分三个事实：用户要求的目标、框架当前选择的执行目标、具体工具实际执行的环境。
宿主平台和项目存储路径不能替代后两者。只查看会影响下一步的现有设置、工具说明与返回；
仍有疑点时，在拟用入口做最小只读探测，例如当前目录、解释器身份或所需编译器路径/版本。
已有输出足够就不再探测。命令未启动时没有目标内证据，不能从宿主结果补推。

| 观察 | 能说明什么、下一步如何选择 |
| --- | --- |
| Windows 上项目目录是盘符路径，项目选择 WSL Ubuntu | 盘符路径可能是框架的宿主坐标；命令应在所选发行版里执行。以工具参数约定和实际返回为准，不能仅看 cwd 是盘符就认定跑在 Windows。 |
| WSL 内 `pwd` 是 Linux 路径 | 只证明该次命令的目录；不证明另一发行版、宿主文件工具或远端调度器使用同一坐标。不要自行把 `/mnt/c` 拼进 Git Bash 安装目录，也不要假定挂载前缀总是 `/mnt`。 |
| 本机发现 Python、编译器、MPI 或 GPU | 只代表这次探测的环境。切到 WSL/SSH、另一发行版或另一工具后，复用前核实与任务有关的部分；Windows 和 Linux 的二进制、venv、动态库及构建缓存不能仅凭同名认作可互换。 |
| Linux/macOS 都提供 Bash 和 `cc` | 不等于编译器、目标架构、链接格式或构建选项相同。只对影响本次构建/运行的差异查证；不要在 macOS 上照搬 ELF 专用检查。 |
| 某个 SSH Slurm 入口可提交作业 | 不证明所有文件工具、同步命令或 Python 工具都已切到那台主机。按当前可见工具与返回核实提交、查询和回传的对象；本地同名文件不能代替远端产物。 |

目录参数和命令中的路径各遵守当前工具的坐标契约；相对路径只有在 cwd 已确认时才消除歧义。
保留引号、空格与 Unicode，不靠改目录名称或移动任务要求的输出位置掩盖转换错误。
路径审批卡若与拟操作的实际目录不同，记录原命令、cwd、目标与返回的差异；额外授权不能修正
错误映射。不要要求永久放行系统/缓存树，也不要自行切换发行版、宿主或服务器来获得成功。
需要用户改变项目目标时提出具体原因；入口确实不支持时交代缺口和未执行部分。

## 失败先找会改变下一步的事实

把失败定位到当前最早的有证据阶段，再选一项区分性检查；不要把它推成所有后续阶段均无问题。

| 最早证据 | 有用的下一步 | 不足以支持的结论 |
| --- | --- | --- |
| 工具在启动前返回路径、授权或 backend 错误 | 核对该入口的目标/路径约定与实际返回，保留未启动事实 | 换壳、改参数或反复批准一定能修复；软件本身必然有错 |
| 配置器拒绝选项或枚举值 | 查当前源码版本的配置定义/官方说明，改相关选项后重配 | 把别的软件/版本的开关套进来；直接跳过官方构建系统 |
| 某个版本查询参数被程序拒绝 | 查该版本支持的帮助入口或已有构建版本记录 | 二进制不可运行，必须重装 |
| 编译/链接失败 | 从首个实际错误核对缺失依赖、头文件、库和 ABI，而非只看最后的构建失败摘要 | 盲换 MPI、删除全环境或无差别重编所有依赖 |
| 断线或同步超时 | 读取既有任务身份、终止及日志事实，再判断是继续观察、取消还是安全重试 | 已失败且无副作用；可以立即重复提交，或加大同步超时代替必要的受管入口 |

诊断用串行、不同库或更小问题可以提供线索，但不能冒充要求的 MPI/GPU/规模验收。
框架能力错误和软件错误可以并存；临时绕过一层后仍须按原任务核对后续阶段。

## 复用经验，同时保留失效条件

临时经验记入已有工作记录，说明适用的软件/版本、执行目标、工具入口、原始错误与证据、
有效修正以及何时应重新核实。无需逐字段填表；只保留影响复用的区别。
例如“此版本 WSL 下某提交入口在启动前误解路径，尚未提交”不能简化成“WSL 不支持 MPI”
或“以后都改同步执行”。升级、切目标、换工具链后，只刷新受影响结论；不把旧 workaround
当永久指令，也不因一个版本失败重复安装已正常工作的软件。
