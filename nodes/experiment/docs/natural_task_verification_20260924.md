# 自然任务验收接线（060，2026-09-24）

## 目标与基线

本包起点 `codex/060-scope-preparation-fix @ 5a8fdd9c`，无 upstream。
修复用户提供的 tilepack / CMake 复测中：真实执行通过、scope 拒绝已消失，
却因 `obligations_not_frozen` 只能 partial 的节点接口缺口。
它不修 benchmark 格式兼容、Reviewer、Core 完成传播或其他节点。

根因：harness 公开任务正文 `experiment_spec`，obligations 却只读取三个内部
结构化数组；启动时容许继续，收尾再要求数组已冻结。`freeze(supplied=...)`
没有模型入口，补 artifact 不能解决，也不应恢复分类或路线手续。

## 最小结构性修改

- A：在原 obligations 文件中保存完整任务正文与来源。有明确结构化要求时
  原样保留；只有自然正文时保存原文义务，不解析成猜测文件名或成功标准。
  optional 项不代替 required，缺内部数组不再被称为用户没有要求。
- B/C：现有 finish 增可选 `verification`，每项引用原要求，并给 file / glob /
  check 核验方法及解释。框架实际核验文件来源、身份与检查结果；模型不能自报
  passed，不写回 A，不替换已有正式检查。方法纠正不重做载荷。
- 共用原证据求值、失败 producer、正式输入、开放作业与三件套事务。检查的
  物理执行各有独立记录，成功后重复 finish 不再执行检查。
- 核验命令复用原 Bash 安全边界及高风险分类，仍在只读工作根中运行。实际
  风险操作回到原执行工具处理，不能把 finish 当审批、远程控制或进程管理入口。
  这是原执行安全政策的接线，不是恢复 route 阶段门。
- 纯 self-test 的真实检查执行也计入执行事实；准入拒绝、未 spawn 的检查不算。
  检查错误同时返回 stderr 与准入原因，避免只给退出码造成无效重试。

模型面不新增工具、分类、预声明、内部身份或调用顺序要求。原任务和具体检查
方法分开，是这次与“收尾临时补写 required_outputs”的本质区别。

## 必须诚实保留的边界

自然语言覆盖是模型的专业解释，不能仅凭原文引句、文件存在或一条通过的
命令机械证明完整。三件套标注 `semantic_coverage=model_interpretation`，保存
完整任务、方法、结果与限制；file/glob 才核验产物 producer，check 本身不
自动证明它所读的每个文件来自本 run。

例如正文要求某个数值，而模型错误地只检查文件存在，仍可能做出错误交付
主张。本包没有增加隐藏的 LLM 裁判或假语义正则，也不能声称已防住任意自然
语言漏项或降标。正式结构化判据仍不可被新方法降低。模型解释质量必须用
真实模型正反任务评估，不能用预填内部数组的单测冒充。

文件只读不等于全面进程隔离；这里复用当前执行准入，不声称静态风险识别能
防住任意隐藏代码的所有副作用。Core 的实际隔离能力声明仍适用。

## 回归与审查

新增自然输入测试不传 scope、required_outputs 或 supplied freeze，通过真实
safe_run_bash 和只读核验进程验证：正确结果、缺项、坏内容、旧文件、失败来源、
方法纠正、正式条件不可覆盖、四种诚实终态、重复 finish、只读边界及纯检查任务。

隔离坏基线 `5a8fdd9c` 的同一批 20 格为 17 红 / 3 绿，修后全绿；其中部分
红是新 schema 未接线，不能全部算原业务缺陷复现。另有原文冻结 15 格、独立
身份与执行准入 8 格。基线反例与 XML 保存在测试记录目录，最终数量见下节。

并行审查发现并修正：派生检查名称与正式要求名称碰撞会丢失失败来源；只读
文件根不能阻止 kill 信号，核验入口必须接既有准入；纯检查已执行但原计数
忽略 finish.check。这些是可达接线缺陷，不是业务样例特例。

本包迁移旧测试中的“有自然正文也必须补内部数组”预期，以及 evaluate 的
新增可选参数；拒绝无证据成功、恢复时核验最终快照的原测试目的不变。
