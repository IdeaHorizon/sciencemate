# 060 受管输出来源检查点（2026-09-23）

## 本片解决什么

产品基线 `a759a7eb79258accb1b9fdbce1211fa53cbdc079`，分支 `codex/060-r3a-c`。
旧 settlement 只在作业终态扫 output roots，再调用 `record_completed_effect`。
它既可能把预存文件认作新产物，又另造一个 exit 0 的本地 action；多条写入之间失败，
重入可能重新观察或再造 action。唯一终态 writer 并没有解决这个来源问题。

这次修复共同事实入口，不增加模型工具、路线、参数表、调用顺序要求或新的执行拒绝。

## 两种方案与决定

最小候选是在旧多事件写法旁加基线与稳定 action ID。它仍保留“作业加一个伪本地 action”
及多次写入的恢复分叉，因此未选。

采用最小结构修复：

1. 复用既有 `submission_attempted` 持久标记，附提交前 output baseline。
   采集发生在脚本/launch 准备之后、实际 scheduler 调用之前，不新建一张授权或状态表。
2. 调度终态、退出事实、输出身份差异放进同一个按 nonce 幂等的 `job_terminal`。
   不再造本地执行 action，也不把 job 的非零退出改成 exit 0。
3. `ledger.project_output_observations` 是纯投影；finish 与科学 provenance 仍消费同一事实，
   不另存一份输出状态。已可见的终态在重入时重新确认持久性，不再扫描后来的文件。
4. 不存在、没看全、探测失败分别记录。跳过的目录不等于空目录；`unknown` 不等于 unchanged。
   同一根里未受影响的新文件仍能正常归属，不因某个排除子树让整个任务降格。
5. 同对象同大小而无内容 hash 的变化不能区分 touch 与原地等长重算，不能单独充当新的内容 producer。
   新大文件仍可按物理新身份记账，不要求所有 HPC 大文件先完整计算 hash。

独立只读终审：accept，限本切片。评审没有替代运行测试，也没有宣布完整 060 已验收。

## 证据

- 最初两个 managed 来源反例在旧实现失败：旧文件被纳入、新内容被记成 created 而不是 modified。
- 6 项 managed 回归通过：预存/新文件、改写、touch、截断基线，以及终态已写下但 ACK 丢失后复入、失败 exit 23 无伪 action。
- coverage 回归先 3 failed / 2 passed，修后 5 passed：排除目录和目录 symlink、不完整观察、显式 unknown、同根正常新文件。
- 内容 producer 回归先 2 failed / 1 passed，修后 3 passed：大文件仅时间戳变化、内容读取失败、新大文件正对照。
- Python 3.11 关键集：60 passed / 4.31 秒，包含自然流程、科学交付、共同终态与上述新回归。
- 节点全量：3803 passed / 19 skipped / 5 个既有 xfailed，145.99 秒。
- 自然流程的作业 success 交付同时核对 C 确实披露观察窗口限制。

测试用真实 State、ledger 和文件，Slurm 响应由 fixture 提供；ACK 丢失和探测错误是明确的故障注入。
没有在本片启动实际 Slurm、模型 UI 或共享服务；不能把这些测试叫作集群或最终用户验收。
本文件内计数对应提交前同一产品内容。精确 HEAD 的跨仓 gate 单独随交接记录，不借用上次 gate。

## 仍然不保证什么

- 快照证明的是提交到首次**持久 settlement 观察**之间的变化，不是物理退出瞬间的完整文件快照。
- 若首份观察根本没成功持久化，重试只能记录后来窗口；不能恢复已丢失的观察。
- 同根窗口差异不能证明排他的物理 writer；旁路或并发写入仍需平台级归属/隔离事实。
- 无 hash 的同对象等长原地更新可能是有效 HPC 重算，但本片不能单凭 stat 宣称已验证内容更新。
  执行仍允许，交付如实说明缺证据；不假装它没有运行，也不偷偷要求模型补内部收据。
- 上述限制进入 C 的 limitations，不仅留在内部终态记录。
- 科学偏离授权、正式输入修订/消费、Core #1141、授权恢复以及最终 UI/Slurm 验收继续按原计划推进。

若未来平台能提供作业级写入身份或退出时冻结 manifest，应消费那个 owner 的事实，替代窗口推断；
不在 Experiment 内另造操作系统写入追踪器。这是进一步替换本方案的条件，不是此次已实现的能力。
