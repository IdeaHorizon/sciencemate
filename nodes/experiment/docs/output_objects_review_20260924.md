# 060：交付对象与核验方法的边界修复

## 范围与基线

产品基线 `b83d1f7c175d0ed27f724aa874a6412d3113b731`；独立实现分支
`codex/060-output-objects`。旧 UI 与证据不变。本批不代表 060 可合并或发布。

实现线负责共同接线，独立 review-a1 只提供反例和复核；测试以真实进程、真实
文件与 B 记录为依据，不用模型结论当 oracle。

## 共同修正

- 执行观察补真实目录身份，仍使用同一 action 边界、预算与排除规则，不扩大写权。
- 目录交付核验文件成员和空叶目录，不将目录当缺失文件，也不靠 exists 直接通过。
  普通中间容器不要求本次新建；已知输入目录可审计而不重造，前后成员身份独立复核。
- 同 inode 目录的 metadata 变化保留创建来源；成功 touch 不能洗白失败 mkdir。
- glob 的最少量条件只选择足量有效候选，显式交付对象仍独立核验；未选失败事实不删除。
- 自然 file 方法默认不附加非空要求；已有正式 required 不变，显式内容条件仍可纠正。
- schema 错误解释合法字段和安全重试形状，不把纠正变成重做载荷。

目录仍是有界观察，不支持任意树完整性证明；超预算、排除、特殊对象、缺失来源
均不冒充完整覆盖。前后快照不能证明全程没有外部并发写入。

## 保留的能力缺口：check-only 遗漏对象

独立诊断 `test_failed_output_is_not_rehabilitated_by_method_correction[object-omitted]`
仍失败：失败动作写出文件，首次明确交付被拒；第二次仅给内容 check 并省略对象，
当前机械评价仍可能支持模型的 success 主张。不得把它统计为已修，也不修改断言
或 xfail 来制造全绿。

不能仅因旧 C 曾关联某对象就把它永久变成 A 的 required。独立真实反证是：本来
只要求算术自检，辅助诊断产生 debug 后失败，模型首次错误交付 debug；纠正为
真实无文件自检应允许完成，不能要求重写 debug、补内部字段或永远只能 partial。

本批不引入该历史关联硬门。失败 B、历史方法和交付限制保留；当前明确对象或
正式条件仍不得绕过失败来源。后一次 shell check 的成功不能机械证明旧失败无关
或已修复；任意 shell 读取依赖和自然语言方法完整性仍未证明。新旧方法都不改 A。
