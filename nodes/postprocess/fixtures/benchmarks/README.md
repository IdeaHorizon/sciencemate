# 出图基准回归集

这五份合同是 **agent 真跑出来的**（不是手写的样本 —— 自造的样本只证明我的理解
自洽，不证明它接得住真数据）。它们各自压到布局引擎的不同一块；任何一条退化，
`test_benchmarks.py` 会指名是哪一条、哪个指标。

| 合同 | 形状 | 压到的东西 |
|---|---|---|
| `calibration-reference.json` | 用户给的参考图逐构件转写 | **判据的标尺**：它永远不许被报出任何缺陷 |
| `topology.json` | 网络拓扑（多栏版面） | 分栏编号、折叠引用、端口、链路捆、引出标注 |
| `flowchart.json` | 数据处理流程 | 判定分支、回退边走外侧、侧边节点 |
| `layered-architecture.json` | 分层系统架构 | 多对多收成总线、侧边一列、嵌套组 |
| `sequence.json` | 课题执行时序 | 参与者横排 + 时间轴、生命线、自环 |

## 重跑 agent 那一层

合同是 agent 的产出，会随模型与 harness 变化；上面钉的是**布局引擎**对同一份
合同的行为。要重跑 agent 那一层（验 agent 还会不会用对词表），用这四条 prompt：

1. **网络拓扑**：双 CPU 服务器插 8 张 RTX PRO6000，每 4 张接一个 PCIe switch
   （共两个），两 switch 间 400Gbps/0.1us；每个 switch 各挂一张 400Gbps RoCE
   网卡；4 台服务器连到 1 台 RoCE 交换机。
2. **数据处理流程**：原始数据入库 → 质量筛查（不合格打回重采）→ 预处理 →
   并行做特征提取与基线模型训练 → 交叉验证（R² < 0.8 回到预处理调参重来，
   达标则产出报告并归档）。标出每个判定点的判据和两条分支。
3. **分层系统架构**：浏览器前端 / API 网关 / 调度器 / 六个执行节点 /
   三样共用基础设施；模型服务在右侧作为外部依赖，被调度器与全部执行节点调用。
4. **课题执行时序**：用户 → 前端 → 调度器 → 执行节点，七步消息；
   「回报进度」可重复，「提交产物」失败时重新派发。

跑法见 `scratchpad/loop/iterate.sh` 与同目录下的 `run-local-probe-*.sh`。
