# SVG 插画轨（AutoFigure 管线移植）

你在这条轨上，当且仅当请求是**纯文字描述的插画/示意图**（briefing 里 track=SVG 轨）。
数据图走 matplotlib 轨（render_figure），spec 驱动的结构图走编译轨——轨道在
declare 时锁定，你改不掉；觉得轨错了就如实告诉调用方，不要换家族绕。

## 工作流（ declare 先行，试渲染免费）

1. `declare_figure_contract(request_id=..., asset_kind=<调用方绑定的>, contract=...)`：
   合同 = 宣言。nodes/edges/groups/assertions 声明这张图必须成立的结构；
   返回里带 `render_guidance.role_colors`（框架发色）与家族清单。
2. **手写 SVG**：按下述 DOM 标记约定与风格规格创作。
3. `render_illustration(..., svg_text=..., trial=true)`：试渲染。返回审计摘要
   （文字出界/碰撞估计、缺字形、标记完整性、**断言预览**）。试渲染不占渲染预算，
   迭代到干净为止。
4. `render_illustration(..., trial=false, caption=..., alt_text=...)`：铸造。
   断言对 DOM 求值、文字政策、字号下限都过了才铸记录；铸造计入渲染预算
   （同一 request_id 与 render_figure 合计最多 3 次）。
5. 可选：`enhance_figure(figure_id=...)` AI 美化（未配置图像模型时它会说
   not_configured —— 那就交付未美化版，它本来就是完整的）。

**环境错误不是你的任务**：工具报 ImportError / bwrap / 只读文件系统这类
**部署环境**错误时，不要自己修环境（不许 pip install、不许删改 site-packages、
不许 rmtree 任何库目录）——如实把错误写进交付说明，拿手上已有的最好结果
继续走铸造/交付流程，或如实告诉调用方"环境缺了什么"。修环境是部署方的事。
铸造时栅格化失败属环境错误：**不扣渲染预算**（返回里 `budget_charged=false`），
但同一请求连续 3 次环境失败会被熔断——那是确定性故障，停止重试、把
`svg_path` 与错误如实交给调用方。

## DOM 标记约定（机械核查，不是建议）

图里每一个有合同身份的元素必须带标记，缺标记即 finding：

- 节点主形状：`data-role="<role>"` + `data-node="<id>"`
- 连线：`data-edge-from="<id>"` + `data-edge-to="<id>"`
- 文字标签：`data-label="<它标注的节点 id>"`（标题/图例等自由文字不打）
- 组容器：`data-group="<group id>"`
- 占位框（图标/插画槽位）：`data-placeholder="<槽位 id>"`

**铁律：合同里声明的每个 id，必须在 SVG DOM 里出现且恰好出现一次。**
declare 时已经枚举过全部 id —— 打标记只是把它们抄进 SVG，不是新增发明。

颜色：节点主形状的角色色用 declare 返回的 role_colors，fill 或 stroke 其一承载。
占位框在 enhancement 缺席时也必须可直接交付（色块 + 居中短标签）。

## 风格规格（参考图预转译冻结文本 v1 · 2026-10-15 · 已审订冻结）

以下来自 AutoFigure `references/paper/` 五张论文参考图的转译（路径 1：转译→
人工审订→冻结；原图存本 skill `references/` 备用）。用户已审订通过，默认
风格 = paper。改这份规格 = 改出图长相，走人工审订流程，别随手调。

- **总体气质**：白底、大留白、低饱和粉彩色块 + 深色细线；学术海报式的克制，
  无渐变、无阴影、无 3D。
- **配色**：组件填充用粉彩系（桃 #FCE9D9 / 浅蓝 #DCE9F7 / 浅绿 #E3F0DA /
  浅黄 #FFF4CC / 粉 #F8E1E7 / 浅灰 #F0F0F0），描边同色系深色或 #333；
  饱和色只给语义标记（红=失败/拒绝、绿=成功、蓝=交叉引用）；角色主形状仍按
  role_colors 框架发色。分区底版用大号粉彩圆角矩形，标题加粗置顶或左上。
- **构图**：单一主导流向（左→右 或 下→上），全程正交，同层组件等距对齐；
  大容器框套子模块（容器 padding ≈ 2× 模块间距）；跨阶段"放大详图"用竖直
  虚线分隔；底部可放阶段带或图例行。
- **连线**：主数据流深色实线箭头（#333，1.5–2px，实心小三角）；迭代/回环/
  引用用虚线；语义不同的边用不同颜色并在图例声明；连线就近入场不穿过组件
  正文；拐弯用直角。
- **字号层级**（三级）：分区标题（粗体最大）> 组件标签（粗体中）> 边注/标注
  （常规小）。组件内文字 = 短名词短语，禁止整句。字号下限按版心机械核。
- **图标槽**：照片/插画/代码块等位图内容走 data-placeholder 占位框，框内短描述。
- **标注习惯**：关键术语可红色强调；数学条件用花括号；步骤用编号圈 ①②。

## 四种内容文体（genre 适配，briefing 已机械识别并推送）

- **paper**（默认）：顶层期刊图版面设计师的克制——少而准的组件、清晰的层级、
  规格写在组件上（sublabel）而非堆图例。
- **survey**：综述图型枚举——分类树（taxonomy）/ 概念框架 / 多面板 / 循环 /
  金字塔 / 对比 / 演进 / 时间线 / 图文目录（TOC）。先定图型再落布局。
- **blog / textbook**：教学优先——布局有序、阅读动线单一；组件与连线避免
  重叠；允许更多解释性文字示例提升可读性。

## 纪律（每条都有机械后果）

- 图上印的数（400Gbps 等）来自文字描述，**不许填 annotated_values** —— 没有
  artifact 出处的声明会被拒铸；不声明，对账缺席会被如实披露。
- 文字政策全局核所有 `<text>`：语言 / 字号（按版心换算）/ 禁用词。
- 需求里带量词的数（8 张 / 两个 / 4 台）每一条都要写成断言，derived_from
  引用需求原文那一小段。
- 词表是有限的：说不出的事写进合同顶层 `unexpressed=["..."]`，别自造字段。
- 美化产物是独立 asset（evidence_bearing=false）；原 figure 永远是机械核过的
  交付品。
