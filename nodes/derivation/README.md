# derivation —— 演绎式取证（第三种证据模态）

> 状态：v0.1，2026-08-22 落地。owner: TBD。
> 设计全文见 `docs/DERIVATION_NODE_DESIGN_20260822.md`。

## 它是什么

取证的第三种模态。种差在**契约**，不在工具箱，也不在学科：

| | 在干什么 | 原罪（特有的作弊方式） | 闸查什么 |
|---|---|---|---|
| experiment | 让世界产生本不会有的新数据 | 伪造执行 | 执行证据闭环 |
| observation | 系统性地看世界已留下的记录 | 摘樱桃 | 取样的系统性 |
| **derivation** | **从已承诺的前提演绎出新命题** | **无效步骤伪装成有效** | **每步要么机械可验、要么显式挂未验**；假设账本全程携带 |

前两套闸对推导**一条也拦不住**：一条 50 步的链每步都真跑过（不是伪造执行）、
引的定理也都真实存在（不是摘樱桃），照样能在第 23 步偷换一个假设。
按平台自己的判据 —— 有独立原罪的取证方式，就是独立模态。

判据是模态不是学科：推导一个统计量的渐近分布是 derivation（哪怕它服务于
一个生物实验），跑一个中世纪贸易的 ABM 模拟是 experiment（哪怕课题是历史学）。

## 核心机制：提一步，验一步

裸模型长推导的死因是**复利崩塌**：每步 99% 正确，100 步后 36.6%。且长程失败
是执行失败 —— 单步正确率还随 context 增长而衰减。所以"一口气写完再检查"是
死路，与模型多强无关。

正路利用数学的根本不对称性 —— **验证远比推导便宜**（Schwartz–Zippel：一个错
等式在随机点上"碰巧成立"的概率趋近零）：

```
提出下一步 → check_step 机械验一遍 → 验过了再走下一步
```

错误在发生的那一步被抓住，而不是 30 步之后；回退成本是一步，不是整条链。
这是把定理证明器的 proof kernel 模式搬到非正式推导上。

## 目录

```
harness.yaml                    契约（prompt / rules / tools / 模式）
tools/derivation_contract.py    冻结门 —— 演绎纪律的机械层
tests/                          冻结门的判据
fixtures/minimal.yaml           量子简谐振子热容（有精确解可对照）
review_spec.md                  审稿规格（★ 这个 reviewer 要跑代码）
```

**验证工具不在这里** —— `check_step` / `find_counterexample` /
`dimensional_check` / `limit_check` 注册在
`shared/tools/library/derivation_check.py`，**全节点共享**。

这是刻意的分工：observation 合并效应量、experiment 核对理论预测、hypothesis
定阈值时验个量纲，都是"顺手算一下"，不该为此起一个 producing run。
**工具共享，证据所有权独占** —— 能产 `derivation_log` 的只有本节点，
这条由 `artifact_policy` 的注册表机械保证。

## 四个判定值

`check_step` 从不返回布尔：

| 值 | 意思 |
|---|---|
| `verified` | 符号层面确证 |
| `numerically_supported` | 符号没结论，随机点上成立 —— **支持，不是证明** |
| `inconclusive` | 两条路都没结论 —— **不等于错** |
| `failed` | 找到反例 —— **强结论** |

最贵的混淆是把 `inconclusive` 当 `failed`：那会让模型去推翻一个正确的步骤、
找一个不存在的 bug。**"我不知道"和"这是错的"是两件事。**

## 门拦什么，各站在哪

不是事后 QC —— 产物写不出错的形状，检查就无事可检。三道门管三件事：

| 门 | 什么时候跑 | 管什么 |
|---|---|---|
| 写入门 | **每次 `save_artifact`（必经）** | 这条链的**结构**成不成立 |
| 冻结门 | `freeze_artifact` 时 | 这份**承诺**兑现了没有 |
| 收尾闸 | 收工前一次（不硬拦） | 切题自查、还红着的式子、日志没冻结 |

⚠️ 结构纪律为什么**必须**在写入面（2026-08-23 真跑事故）：它原本只挂在冻结门上，
而冻结是模型自愿调用的一个动作。那一趟里模型真的调了 9 次 `check_step` 逐步验过，
却把 `step.verification` 写成字符串 `"verified"`（丢掉工具返回的章、只手抄一个
结论词），然后 save 两次、**从头到尾没调 `freeze_artifact`** —— 那道判据一个字
都没写错的门，**一次都没跑**，产物带着伪造的验证章交付、run 判 completed。
闸放哪层按**对手是谁**推：对手是"不冻结就交付"，写入是必经的，冻结不是。

判据只写一份，两道门共用同一批函数（`_audit_steps` 等）。

1. **验证章只认工具落的**：`verification.tool` 必须是注册在案的验证工具。
   模型自己写 `status: verified` 进不来 —— **报告不是事实**。
2. **每步要么有章，要么显式挂未验**（justification 标 cited_theorem / prose /
   definition）。**未验不是罪，装作验过才是。**
3. **适用域由框架现算** = 沿链累积的活假设并集。模型手写的必然漂移，
   而"适用域静默扩大"是最难人眼发现的一类错。
4. **数值支持不能冒充演绎**：主结果只有数值支持时 credibility 必须交代。
5. **被证否的步骤不能留在链上**当结论。
6. **exploratory 不许勾账**（anti-HARKing 在演绎侧的形态）。

## 两种模式

| mode | 在干什么 | 能不能勾账 |
|---|---|---|
| `exploratory` | 找猜想、找形式：数值实验找规律、特例摸底 | ⛔ 不能 |
| `confirmatory` | 对照冻结命题给出验证链并裁决 | ✅ 能 |

探索出来的猜想交给 Analysis 立成研究问题、冻结闭合条件，再起一趟 confirmatory
run 兑现。**这条路径是正路，不是绕路。**

## 边界：它不做什么

| 不做 | 为什么 | 该找谁 |
|---|---|---|
| 不产生新数据 | 需要让世界产生新数据 | 交回调度器派 experiment；**不得用 execute_python 跑出一份"新数据"充数**（exploratory 用数值实验**找形式**是允许的，当**证据**不允许） |
| 不翻 claim status | 科学终态归 Analysis | 只出执行层 verdict + credibility（与 experiment / observation 完全对齐） |
| 不自己写论文 | 产物是证据记录 | writing |

## 与其他节点的关系

- **上游**：Analysis 冻结 prereg → 派 derivation。理论先行的课题，
  derivation 先导出预测（预测本身成为 prereg 阈值的来源），再派 experiment 检验。
- **下游**：`derivation_log` 回流 → Analysis 裁决科学终态；writing 消费。
- **供料**：`callable_nodes: [literature, data]` —— 查一条定理的出处、
  看这个结果是不是已经被证过，是推导过程中最高频的外部需求。
- **跨模态互证**：推导出的解析结果交给 experiment 数值模拟原问题对照 ——
  "符号推导 vs 直接数值"双路一致是最强的非正式证据。写成 prereg 的陈述条。

## 六个验证后端，谁能证成谁只能证否

| 工具 | 证成 | 证否 | method | 严格性 |
|---|---|---|---|---|
| `check_step` | ✅ CAS 默认假设下 | ✅ | symbolic / numeric | 强 / 抽样 |
| `dimensional_check` | ❌ | ✅ | symbolic | 严格（量纲错=式子错）|
| `limit_check` | ❌ | ✅ | symbolic | 严格 |
| `find_counterexample` | ❌ | ✅ | numeric | 严格（给出反例点）|
| `interval_check` | ❌ | ✅ | interval | **严格**（整个区间）|
| `check_lean` | ✅ | — | formal | **最强**（形式化内核）|

中间四个**只在证否侧盖章**：量纲对、极限对、没找到反例、区间含 0 —— 全是
必要条件而非充分条件，盖成 verified 就是语义膨胀（模型会拿"量纲对了"
当"这步验过了"）。而它们证否时是强结论。这与「验证不对称性」同源。

**白名单是现算的，不是手写的**（`shared/lib/verifier_registry`）：有资格署名
⟺ 这个工具真的注册了自己会往账本写。能力缺席（没装 python-flint / 没有 Lean
工具链）→ 工具不注册 → 名字不在白名单 → 模型手写它当场被拒。
2026-08-23 之前 `check_lean` 只是名单里的一个字符串，那是一条只在账本失灵时
生效的后门。

### interval_check 的能力边界

区间算术是**外包围**，所以只能证否。而且有**依赖问题**：同一个变量出现多次时
每次出现被当独立变量，区间会被严重放大。实测 `exp(x+y)` vs `exp(x)+exp(y)`：

```
x,y ∈ [1, 2]    → [±49.2]     含 0，证否失败
x,y ∈ [1, 1.01] → [2±0.103]   严格证否
```

证否失败先怀疑区间给太宽，分段收窄再逐段验。

### check_lean 的信任边界

⚠️ **在陈述，不在证明**：Lean 证的是你写下的那个形式化命题，不是你以为的
那个自然语言命题。翻译错了它照样全绿，而且绿得很有说服力 —— 所以章里必带
`formal_statement` 原文，**要核对的是那一行**。`sorry` 是占位符，识别成"没证"。

本机是裸 Lean 4，**没有 mathlib**：命题逻辑、基本算术、结构归纳这一档可用；
实分析/测度论/群论的成套引理不在。
