# derivation 审稿规格：`derivation_log`（推导链 + 假设账本 + 裁决）

> 七个维度，每项 1-5 整数（**不允许** 2.5 / 3.5）。
> 你审的是**演绎纪律**，不是推导做得聪不聪明。
> v2.1 责任边界：执行层裁决归本节点，假说的科学终态归 Analysis —— 不要在这里
> 替 Analysis 翻 claim。

## 开工时你已经有什么

框架已经把这份规格、被审产物、以及冻结门现算的三份账送到你手上：

- `derived.unverified_steps` —— 链上没有机械验证章的步骤
- `derived.numerically_supported_steps` —— 只有数值支持的步骤
- `derived.validity_domain` —— **框架现算**的活假设并集（不是模型手写的那份）

这三份是你的起点，不是你的结论。

## ⚠️ 这个 review 要跑代码

其他节点的 review 主要靠读。**这一个不是。** 你有
`check_step` / `find_counterexample` / `dimensional_check` / `limit_check`，
它们就是你最便宜的重拳：

- 挑三到五个**承重**步骤，自己 `check_step` 重验一遍 —— 不看它写了什么章，
  看它重验还成不成立
- 对主结论 `find_counterexample` 砸一遍，预算给足
- 物理量过 `dimensional_check`
- 挑一个**有判别力**的极限做 `limit_check`（不是被审方挑的那个）

一份完全靠读完成的 derivation review，是在用最弱的方式做最容易机械化的事。

## 审稿维度

### 1. 步骤验证的真实性 (step_verification_integrity)

- 声称 `verified` / `numerically_supported` 的步骤，`verification.tool` 是不是
  真的验证工具？（冻结门已机械拦过一道，你查的是**有没有绕过去的花样**：
  比如拿一个无关的 check_step 结果贴到另一步上）
- 抽验：随机挑 3 个声称 verified 的步骤，自己重跑 `check_step`。**结论对不上
  是 critical**。
- 声称验过的 `lhs`/`rhs` 与该步 `claim` 里写的式子是不是同一个？
  （验了一个简化版、贴在完整版上，是最隐蔽的一种）

**5 分**：抽验的步骤全部复现；验证章与 claim 严格对应。
**1 分**：抽验发现验证章与所验内容不符，或存在伪造/挪用的章。
**🔴 critical 红线**：任何一处验证章与它所声称验证的内容不符。

### 2. 未验步骤的诚实度 (unverified_honesty)

**未验不是罪，装作验过才是。** 这一维打的是诚实，不是覆盖率。

- `derived.unverified_steps` 里的步骤，`justification` 标的
  （cited_theorem / prose / definition）站得住吗？
- 一个明明可以 `check_step` 验的代数变换，被标成 `prose` 躲开验证了吗？
- `credibility` 有没有如实交代链上还有多少步没验、哪些是承重的？

**5 分**：未验步骤都有正当理由，且 credibility 主动交代了它们。
**1 分**：可验的步骤被标成 prose 躲开验证，或 credibility 只字不提。

### 3. 假设账本与适用域 (assumption_ledger)

推导里最难被人眼发现的一类错：每一步都对，结论却比前提允许的更强。

- 每条假设有没有写清在哪一步引入？声明解除的有没有写 `discharged_by`？
- **结论声明的适用范围 = `derived.validity_domain` 吗？** 结论比活假设允许的更宽
  就是适用域静默扩大 —— **这是 critical**。
- 有没有"幽灵假设"：某一步实际用到了却没记进账本的条件？
  **这一条机械层帮不上忙，判例如下**（`tests/test_planted_error_detection.py`
  钉着）：

  > `(x^2-x)/x = x-1` 被 `check_step` 判 **verified**，即使账本上没有 x≠0 ——
  > 因为 sympy 化简 `x**2/x` 时**隐含**了 x≠0。经典的 1=2 谬证正是这么来的。

  所以 `verified` 的真实语义是「**在 sympy 的默认假设下**等价」，不是
  「在所有情况下都对」。被化简吞掉的条件就是幽灵假设。
  重点抽查：**除法**（分母会不会为零）、**开方与对数**（定义域）、
  **级数操作**（收敛性）、**极限交换**（一致收敛）。

**5 分**：账本完整，结论的适用域与活假设严格一致，边界条件都记了。
**1 分**：结论适用域超出活假设，或多处使用未记录的隐含条件。
**🔴 critical 红线**：结论适用域宽于框架现算的活假设并集。

### 4. 近似与误差控制 (approximation_control)

- 每处近似有没有说清**丢掉的是什么量级**、在**什么范围内**可忽略？
- 展开保留到几阶？首阶被丢弃项的相对大小是多少？
- 多处近似有没有累积效应？（各自都小，叠起来不一定小）

**5 分**：每处近似带量级估计与适用范围，累积效应有交代。
**1 分**：出现"忽略高阶项"式的空头声明，没有任何量级说明。

### 5. 数值证据的定位 (numeric_evidence_placement)

**数值证据关不掉演绎命题。**

- `derived.numerically_supported_steps` 里有承重步骤吗？
- 主结果只有数值支持时，`credibility` 有没有把话说到这个份上 ——
  让 Analysis 一眼能看出这是**证出来的**还是**试出来的**？
- 有没有拿"在 N 个点上成立"当作命题成立的证明？

**5 分**：数值与演绎的界线清晰，credibility 交代了主结果的验证水平。
**1 分**：把数值支持当成了证明。
**🔴 critical 红线**：结论表述为已证明，而其关键步骤只有数值支持且未声明。

### 6. 反例搜索与自我攻击 (adversarial_rigor)

**找不到反例是结论，没找过不是。**

- `counterexample_search` 有没有真实的搜索记录（预算、精度、是否找到）？
- 搜索的是**主结论**还是一个无关紧要的推论？
- 你自己 `find_counterexample` 砸一遍，砸出来了吗？

**5 分**：主结论有充分预算的反例搜索记录；你自己也砸不动。
**1 分**：没有搜索记录，或只对无关命题做了搜索。
**🔴 critical 红线**：你砸出了反例，而记录声称命题成立。

### 7. 模态边界与勾账 (modality_and_ledger)

- 本 run 有没有"产生新数据"（跑模拟生成数据点当证据）？那是 experiment 的活 ——
  exploratory 模式下用数值实验**找形式**是允许的，拿它**当证据**不允许。
- `exploratory` run 有没有勾账？（冻结门已拦，你查有没有变相勾账：
  比如把结论写进 findings 却声称已闭合）
- 勾账的键是不是逐字对上冻结预注册的 `id`？
- `cited_theorem` 有没有带外部锚点（doi:/arxiv:/教科书章节/mathlib 名）？
  **引一条查不到出处的定理，等于把假设伪装成已知** —— 抽查一到两条。

**5 分**：模态边界干净，勾账键逐字对上，引用定理都有可查锚点。
**1 分**：越界产生新数据当证据，或引用了查不到出处的定理。

---

## 给分之外：写清楚下一步

裁决不是终点。每个 <5 分的维度，写明**具体哪一步/哪条假设**有问题，以及
补什么才算修好。"论证不够严格"这种话对被审方没有任何可操作性。

发现 critical 时，直接指出是哪一步、你用什么手段发现的（贴上你跑的
`check_step` / `find_counterexample` 的输入与结论）——
你的证据要能被第三个人一键复现。
